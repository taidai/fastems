# FastEMS 产品规格 v1（范围冻结）

版本：2026-11-04 · 状态：**已冻结**
本文是当前唯一权威的产品规格。与此前任何 IoT/SCADA 草图、规划或讨论冲突时，以本文为准。

> 实施状态：本文只定义目标与验收，不代表已完成。当前进度、证据、未完成项与过渡边界以 `GOAL.md` 为准；M4 分步验收见 `docs/m4-acceptance.md`。

## 1. 一句话目标

**让实施人员在一台工控机上，把光储充现场接进来、看清楚、控得住、留下痕迹。**

展开说：不需要写代码，用业务树描述现场，用决策表表达“什么情况下做什么”，系统负责安全限制、把目标分给设备、回读确认，并让每一次动作都能解释。

## 2. 要解决的问题

现场实施和运行目前依赖工程师经验：

- 每接一台设备都要查协议、试串口、猜地址。
- 控制逻辑散落在各项目代码里，换品牌就要改程序。
- 出了故障，只能看到“没动作”，说不清为什么没动作。
- 上层要看的总功率、总 SOC 要重新算一遍，和下面显示的对不上。

FastEMS 要把这些变成配置和可解释的运行。

## 3. 用户

| 用户 | 做什么 | 看到什么 |
| --- | --- | --- |
| 实施/集成人员 | 接线检测、设备接入、点表、规则配置、验收、排障 | 通道诊断、原始值、Profile、规则编辑器、验收报告 |
| 操作员 | 看运行、处理报警、授权范围内操作 | 画面、报警、趋势、受控操作与回读结果 |
| 管理员 | 账号、权限、备份、交付检查 | 用户与范围、系统状态 |

首要用户是实施人员，日常使用者是操作员。产品面向独立交付，不要求最终客户修改源码。

## 4. 核心概念（白话版）

### 4.1 通道

一条真实的通信路径。可能是 COM3 上的一路 RS485，也可能是 192.168.10.11:502 上的一个 Modbus TCP 连接。

通道数量由现场硬件决定，产品不写死。一条 RS485 总线上的请求串行，不同通道之间并行。

### 4.2 设备

挂在通道下的一台从站或逻辑设备：PCS、BMS、电表、光伏逆变器。

设备记录自己的站号、型号、健康状态，并声明自己**能读什么、能写什么、能执行什么命令**。命令包含参数、期望回读、超时和失败状态。

厂家差异由设备 Profile 和驱动承担，业务规则不感知寄存器。

### 4.3 点位

设备上的一个数据或控制目标：值、单位、质量、来源时间、读写方向、范围。

质量分为正常、过期、无效、未初始化。**过期数据不会被当作实时数据参与新的自动控制。**

### 4.4 业务树与虚拟设备

业务树按现场怎么用组织：园区 → 光储充站 → 储能区 → 储能柜 → 设备。层级不限。

任意层级都可以有实时点位和派生点位。没有物理设备的层级建成**虚拟设备**，用受控聚合计算得出自己的值：

- 求和、平均、最小、最大、计数
- 输入带质量与时效；部分输入无效时结果标记“部分有效”
- 展示可以用部分有效值；用于安全控制时默认要求输入完整

v1 中虚拟设备**只读**，不作为控制目标。

### 4.5 决策表

用“如果……并且……就……”的行表达业务规则：

- 同一行条件全部满足才算命中，从上到下首条命中即停止
- 条件支持数值、布尔、枚举、设备状态
- 条件需持续 N 秒才命中（避免抖动）
- 同一行触发后有冷却时间（避免频繁动作）
- 每次执行记录输入快照：值、质量、来源时间、规则版本
- 模拟使用当前草稿与真实引擎计算，绝不写设备

决策表的输出是**请求**，不是最终命令。

### 4.6 分配器

解决“一个总目标怎么分给多台设备”。

```text
决策表：储能系统放电 800 kW
        ↓
分配器：读取每台 PCS 当前可用放电功率
        排除离线与故障
        按可用功率比例分配
        夹到各自上限
        剩余功率再次分配
        ↓
每台 PCS 收到自己的目标值，逐台回读
```

- 分配器挂在业务节点上（如“储能系统”），成员是节点下的 PCS，权限跟随树范围
- 决策表按稳定业务 ID 绑定分配器
- 分配器是该组输出的唯一自动所有者；其他地方直接写这些点位会被拒绝
- 成员短暂失联先在宽限期内保留目标，超时后剔除并重新分配，记录原因
- 充放电用带符号功率表达：正为放电，负为充电

### 4.7 安全层

决策表的请求必须经过安全层才能变成命令：

- 数值范围与设备能力上限
- BMS 允许充放电功率、SOC 上下限、温度约束
- 设备在线与数据有效
- 输入时效
- 输出所有权

被限制时不是静默截断，而是记录“为什么被限制”。

### 4.8 四类功率

| 名称 | 含义 |
| --- | --- |
| P_request | 业务或规则希望多少 |
| P_target | 经过所有权与仲裁后的目标 |
| P_command | 经过安全、限功率、爬坡后的实际下发值 |
| P_actual | 设备实际回读值 |

系统必须能回答：为什么请求 500 kW，最终只执行 300 kW。

### 4.9 命令

启停、并网、复位这类动作用命名命令表达：写哪些点位、期望回读什么、超时多久。

- 命令状态：已接受、执行中、已回读、失败、结果未知
- 通信中断时结果为“未知”，不自动重复写入
- 命令的执行记录可追溯操作者、请求 ID 与回读值

### 4.10 调试 / 运行模式

按节点设置，不按整个实例设置。

- 调试模式：允许扫描、测试、点动；受影响范围内的自动输出暂停
- 运行模式：正常执行决策表；禁止可能影响通信与控制的危险扫描

不做 Shadow Mode。

## 5. 一条运行链

```text
现场设备
  ↓ Modbus RTU / TCP
通道（串行调度、超时、错误统计）
  ↓
设备（Profile、站号、健康、能力、命令）
  ↓
点位（值、质量、来源时间）
  ↓
业务树 / 虚拟设备（聚合、派生）
  ↓
决策表（条件、持续、冷却、首条命中）
  ↓
安全检查（范围、能力、SOC、时效、所有权）
  ↓
分配器（一个目标 → 多台 PCS）
  ↓
命令（写入、回读、超时、结果未知）
  ↓
报警 / 历史 / 画面 / 审计
```

## 6. v1 交付范围（冻结）

| V1-5 | 虚拟设备与聚合 | 求和、平均、最小、最大、计数；质量与时效传播；部分有效标记；只读 |
| V1-6 | 分配器 | 成员为 PCS；按可用功率比例分配；排除离线；夹到上限；宽限期后重分配；逐台回读；可解释 |
| V1-7 | 报警与事件 | 离线、数据过期、越限、控制失败、命令未知、规则异常；产生、恢复、确认、关闭；去重与历史 |

| V1-10 | 权限与审计 | 本人账号；管理员/实施/操作员/查看者；树范围授权；服务端默认拒绝；配置与控制留痕 |

### 视觉与交互约束（V1）

> 2026-11-04 用户确认采用**玻璃拟态控制台**：浅色磨砂玻璃浮在站点照片上。参考图 `docs/assets/energy-console-reference.webp`，背景图 `docs/assets/ems-site-photo.jpg`；完整规范见 `docs/ui-theme.md`。

- 浅色半透明玻璃面板，背景为模糊的站点照片；文字使用深色墨，不回到纯白卡片堆叠。
- 琥珀色仅用于品牌、当前选中与需要注意的状态；数据文字保持中性深灰。
- 顶栏包含品牌、站点选择、目录与账号；KPI 条与站点能流是总览核心。
- 语义色固定：绿色=光伏/正常，蓝色=储能，青色=负载/充电，灰色=电网/未接入，红色=严重告警。
- 没有数据的节点显示“—”，模拟/估算值必须显式标注，不冒充实测。
- 按 10.1 寸触摸屏设计：基准 1280×800，最小可点区 44×44 px，卡片间距不小于 12 px。
- 高信息密度但层级清楚；避免高饱和霓虹和装饰性渐变。

## 7. v1 不做

- 云端平台、多站集中管理、OTA、远程运维
- 时间窗口（峰谷时段、星期、跨午夜）——v1.1
- 内置 EMS 策略模板（防逆流、需量、峰谷套利、光储跟补、SOC 均衡）——v1.1
- 自由拖拽的拟态画面编辑器
- 充电桩驱动与 OCPP（无协议资料，仅保留能力语义）
- 预测、优化、AI、电力交易
- Shadow Mode
- 任意脚本 / 自由公式
- 多租户

## 8. 验收

### 8.1 模拟场景（可重复回归）

4 台储能柜：2 台正常、1 台离线、1 台限功率。

1. 决策表请求储能放电 800 kW。
2. 分配器排除离线柜、夹到各柜上限、按可用功率比例分配。
3. 剩余功率重新分配，总下发值不得超过物理能力。
4. 每台 PCS 回读值与目标值的关系可解释。
5. 越限输入、过期输入、离线设备均阻止新动作并记录原因。
6. 模拟不产生任何命令。

### 8.2 真实设备链路（最终签收）

- 恩玖 PCS
- 储能 BMS（ESBCM 协议）
- 至少一台电表（TOKY / DTSD3366D-J / D□SD9866 / YD2037Y 之一）
- 华为光伏逆变器

需要完成：采集、控制、回读、断线、恢复、过期阻断。

模拟器通过不替代真实链路；真实链路通过也不代表更多品牌已支持。

### 8.3 通用门槛

- 浏览器完成真实操作，不只是单元测试
- 断线、超时、重复提交、越权、重启恢复均有测试
- 完整数据目录离线恢复经过验证
- 不泄露密码、令牌与连接凭据

## 10. 技术约束

- 一个 Encore 服务承载生产的 HTTP 入口；服务内嵌 Simple IoT、NATS/JetStream、EMS 运行时与前端，不增加第二业务服务或外部消息队列。2026-11-06 起不再以 Windows 单 exe 作为生产交付物，见 `docs/encore-migration.md`。
- 内嵌 JetStream 作为唯一存储；配置、报警、命令、审计仍以 Point 表达。先做容量与查询实测，不足再评估第二存储。
- 先支持 Modbus TCP/RTU；协议与通道模型保持可扩展。
- 控制周期 1 秒；关键点位 1 秒采集；慢变量 5–60 秒；历史按变化 + 最小间隔归档；按点位设置保留上限。
- 保留已验收的鉴权、业务树、历史、账号、交付检查接口；重写规则与设备模型接口。
- 测试用 Modbus 模拟器随源码提供，不进入产品界面，不冒充真实设备。

## 12. 变更规则

- v1 冻结后只修缺陷，不新增需求。
- 新需求进入 `v1.1 候选` 清单，按“是否影响现场安全与验收”排序。
- 任何改变本文件边界的决定，必须先更新本文件，再改代码。
