## 2. 点位能力增强

### 用户需要看到的内容

- 业务名称、稳定业务 ID、数值/布尔/枚举/文本类型。
- 单位、精度、有效范围、只读/可写/读写方向。
- 当前值、目标值、更新时间、来源和连接状态。
- 数据质量：正常、不确定、无效、过期；异常时不得沿用旧值进行新的自动控制。
- 原始来源与加工关系：直接、倍率/偏移、枚举解码、多点组合、受约束公式。
- 派生点依赖图必须无环；换品牌只改来源/加工绑定，不改业务 ID、规则和历史归属。

### 不新增平行实体

这些仍是现有点位的 Point 或配置字段：质量、来源时间、加工版本、有效范围、方向、绑定与最近命令。原始值、标准值和控制状态使用已有 `value`、`valueSet`、`lastCommand` 及历史流，不建立另一套设备对象体系。

### 控制边界

- 可写点必须确定唯一控制目标和安全范围。
- 非有效/过期/禁用输入不触发新动作。
- `valueSet` 只表示目标；只有新的 `value` 回读匹配才表示已回读。
- 模拟永远不创建命令或控制记录。

## 3. 决策表能力增强

保留现有：多输入、行内 AND、多输出顺序、首条命中、排序、默认不动作、草稿/发布/启用/模拟、人工接管与版本恢复。

新增顺序如下：

1. **触发方式**：点位变化 + 固定节拍巡检；无新数据也能检查当前有效状态。
2. **持续时间**：条件持续达到设定时间才命中，避免瞬时抖动。
3. **冷却与限频**：按策略或输出限制频繁启停；冷却期间状态仍可观察。
4. **时间窗口**：使用站点本地时间，支持跨午夜；不暴露 Cron 表达式。
5. **输入快照**：记录每个输入的值、质量、来源时间和策略版本。
6. **输出所有权**：同一可控点位同一时刻只能由一个已启用策略拥有，启用时由服务端强制校验。
7. **顺序回读**：前一动作回读成功后才执行下一动作；失败停止后续动作，不自动倒序回滚。
8. **失败状态**：READY、BLOCKED、FAILED 与启用状态分开；FAILED 需要处理原因后显式恢复。

### 明确不做

- 不引入第二套 JDM/GoRules 运行时。
- 不增加自由脚本、动态目标、循环、等待或任意 HTTP/设备动作。
- 不做简单模式/完整图双向转换。
- 不把规则引擎扩展成通用流程画布。

## 4. 完全吸收 Simple IoT 用例的方式

“吸收用法”是吸收其运行模式和边界，不是开启所有客户端：

| Simple IoT 用例/能力 | 产品吸收方式 |
| --- | --- |
| 本地自治 | 采集、规则、控制和存储在单实例本地运行，网络异常不依赖云端才能工作。 |
| 离线积压与续传 | 当前保留本地历史；未来有多站点需求时再启用 Sync，并验证断网缓存、顺序和权限。 |
| 远程配置待连接后下发 | 只有引入受控上游连接后才实现；不能把任意 URI 同步当作普通配置。 |
| 有界历史 | 按点位采样率解释默认 20,000 条能覆盖多久，监控用量并制定保留策略。 |
| 外部应用集成 | 有真实应用时通过受控接口集成；不公开内部 NATS 给普通用户。 |
| 灌溉、楼宇、车辆、工厂等场景 | 由设备模板、点位和规则配置表达，不为每个行业复制底座。 |
| 多上游/多层级网关 | 上游明确标为未来设计，当前不宣称支持。 |

## 5. 实施与验收顺序

1. **点位与质量**：先完成类型、质量、时间、来源和加工展示；断线、过期、非有限值与换绑均有测试。
2. **规则运行语义**：持续时间、巡检、冷却、输出所有权、顺序回读和失败恢复逐项验收。
3. **派生点位**：仅在真实多点计算需求下实现受约束公式和 DAG；禁止任意脚本。
4. **可选外部能力**：Sync、MQTT、外置数据库只在具体需求驱动下分别验收。

每项均要求：真实浏览器操作、失败路径、权限边界、重启恢复和证据。草图只用于确认方向，不冒充功能已完成。
