# easyems 领域模型重构 · 定案

日期：2026-11-08
状态：14 个决策经 grill 定案，作为重构实施的共识基线。

## 背景

easyems 当前领域模型是「通道 → 站号 → 点位」的 Modbus 通道导向模型（设备 = 通道+站号隐式组合，无 EnergyUnit 抽象，无稳定资产 ID）。目标模型（领域模型图）是「Site → Plant → EnergyUnit → Device → Point」的能力/业务导向模型，核心原则「调度对象是 EnergyUnit，而不是具体设备型号」。

## 目标数据模型

```
Site 场站（调度层）
 └─ Plant 电站（调度层）
     └─ EnergyUnit 柜体/能源节点（调度对象）
         ├─ asset_code（稳定业务 ID）
         ├─ Capability（汇总：额定 + 动态）
         └─ Device 设备（一等节点）
             ├─ asset_code（稳定 ID）
             ├─ Profile 绑定 + 实例覆盖的额定能力
             └─ Point 点位（挂设备下）
```

## 三个高风险点（用户反推荐，有意为之）

1. **Q3=B 破坏性重构**：现有 M4 证据作废重跑，存量数据清空，重构期间不可交付。
2. **Q8=B + Q10=B**：三层节点 + 站级/电站级调度算法一次做，工作量 = 领域模型 + 能源节点调度 + 站级调度。
3. **Q7=A 只储能**：站级调度第一版只对储能生效，光储充联合（MIX-01）待光伏/充电节点补齐。

## 实施阶段（初稿，待技术调研细化）

1. **领域模型核心**：新增 site/plant/energyUnit/device 四类 node；Capability 模型；asset_code。
2. **调度语义切换**：规则/分配器从点位级改为能力级（引用 EnergyUnit.Capability）。
3. **站级/电站级调度**：Site Scheduler（总目标/防逆流/需量/跨站）+ Plant Scheduler（功率分配/柜间协调）。
4. **验证**：重建模拟器，M4 证据重跑 + 新调度验证。
