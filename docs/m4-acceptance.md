# M4 部署与验收计划

目标：空实例在一台工控机上完成“接入 → 点位 → 画面 → 报警/历史 → 验收报告”，并证明重启后配置和运行状态可恢复。

## 验收前提

- 固定版本二进制 `easyems.exe`，单个 HTTP 入口，内嵌前端。
- 空数据目录启动；首次启动生成管理员初始密码，密码不写入文档、日志或导出。
- Modbus TCP 模拟器监听 `127.0.0.1:1502`，保持寄存器 10 = 253（缩放 0.1 后 25.3）。
- 真实设备链路不在本轮自动化范围；模拟器结果单独标注，不冒充实机。

## M4-1 生命周期与持久化

1. 空目录启动，`/api/health` 返回 ready，未配置任何通道。
2. 通过 API/UI 新增一条 Modbus TCP 通道（含 1 台设备、1 个保持寄存器点位）。
3. 重启进程，`/api/ems/channels`、`/api/ems/state` 恢复同一条通道和点位；运行周期继续。
4. 画面配置 `easyemsScreen`、规则、报警、历史在重启后仍可读。
5. 通过：重启前后配置 ID、点位、缩放、站号一致；无第二套存储或旁路 API。

## M4-2 扫描与识别

1. 对通道地址做站号扫描（1–247，支持限定范围），只读，不写设备。
2. 读取标识寄存器；匹配 Profile 后给出设备型号/能力建议。
3. 读不到标识时允许人工选择 Profile，不阻塞接入。
4. 通过：扫描结果可解释；失败返回原因；运行模式下不执行危险扫描。

## M4-3 点表校验

1. CSV 点表两阶段：预检（地址、类型、站号、缩放、重名）→ 确认导入。
2. 预检失败不写入任何点位；导入原子化。
3. 导出当前点表与导入格式一致。
4. 通过：错误行有行号和原因；导入后点位可读；导出可回导。

## M4-4 验收报告

1. 一键运行：接口检测、通道通信、点位质量、规则发布、报警/历史、备份状态、权限边界。
2. 报告包含通过/警告/失败、证据时间、对象名称；不包含密码、令牌、连接凭据。
3. 失败项可定位到设备/点位/通道，并给出下一步。
4. 通过：空实例完整跑通；报告写入 `evidence/`；浏览器可查看。

## M4-5 回归

- `go vet ./...`、`go test ./...`、前端生产构建。
- `frontend/browser-smoke.mjs` 在干净数据目录全项通过。
- M3 页面（报警、历史、画面）与新增通道页无控制台错误、无 4xx。
- 重启、断线、过期、重复提交、越权均有失败路径证据。

## 证据命名

- `evidence/m4-lifecycle.txt`：重启前后通道/点位/画面配置。
- `evidence/m4-scan.txt`：扫描与 Profile 匹配。
- `evidence/m4-point-table.txt`：预检失败与成功导入。
- `evidence/m4-acceptance.png`：验收报告页面。
- `evidence/m4-acceptance.json`：机器可读结果。
