# 通用 IoT 底座：完整功能规划

> **历史规划（2026-11-03）**：本文是早期“通用 IoT 底座”的功能地图，保留作能力参考；当前产品为光储充 EMS 底座，运行不依赖 Home Assistant，范围与验收以 `docs/product-spec-v1.md` 与 `GOAL.md` 为准。

> 2026-11-04 更新：产品目标已重新确认为光储充 EMS 底座，首要能力是通用决策表格引擎。本文件保留原有完整功能地图作为能力参考，实施顺序需按新的产品目标确认结果重排。

版本：2026-11-03

## 1. 产品目标

让没有开发经验、也没有 IoT 平台经验的人，能够通过界面完成：

**接入设备 → 建立业务模型 → 查看和操作 → 配置自动控制 → 发现和处理异常 → 授权交付 → 备份维护。**

底座不是协议调试工具、工程后台或源码生成器。默认交付单应用、内嵌界面、无需 YAML/代码、无需共享管理员令牌。

### 产品边界

- 通用业务层不绑定能源行业；能源、楼宇、农业、环保等场景使用同一套设备树、点位、规则和权限。
- 用户配置的是“温度、湿度、水位、开关”等业务对象，不是寄存器或平台内部对象。
- 底座负责连接、状态、控制、自动化和运维，不试图替代 ERP、工单系统、BI、数字孪生或视频平台。
- 高风险控制必须具备明确的权限、输入有效性、人工接管、失败反馈和审计，不能只做页面上的开关。

## 2. 角色与最终工作流

| 角色 | 主要工作 | 默认边界 |
| --- | --- | --- |
| 管理员 | 初始化、账号、全局配置、备份恢复 | 仅限管理员 |
| 实施/运维人员 | 接入、建模、换绑、规则、诊断、处理异常 | 按项目范围授权 |
| 操作员 | 查看状态、执行允许的控制、接管设备 | 只能操作授权点位 |
| 查看者 | 查看授权设备、历史、告警和规则状态 | 只读 |

### 首次使用

1. 创建管理员，设置实例名称和时区。
2. 选择连接类型，测试连接。
3. 导入点表或从模板添加点位，预览后确认。
4. 检查实时值，执行受控测试。
5. 创建决策表，模拟、发布、启用。
6. 创建最终用户并按项目/区域授权。
7. 完成交付检查和备份。

### 日常使用

打开工作台即可知道：设备是否正常、哪些自动控制正在运行、有没有异常、最近发生了什么。用户不需要理解 Node、Point、NATS、寄存器或规则实现。

## 3. 完整功能地图

### A. 实例与初始化

- 首次初始化向导，不允许保留上游默认密码。
- 实例名称、Logo、语言、时区、单位和日期格式。
- 管理员修改本人密码；管理员可重置他人密码。
- 会话过期、退出和异常登录提示。
- 运行状态、版本、存储用量、运行时间和资源状态。
- 单应用健康检查；启动失败不得误报就绪。

### B. 多层级业务模型

- 任意层级树：集团/项目/站点/区域/系统/设备等节点由用户定义。
- 分组和设备支持新增、重命名、移动、复制、停用和删除。
- 移动或删除前展示子节点、规则、账号授权和告警影响；有依赖时默认阻止。
- 设备详情包含来源、点位、动作、实时状态、历史、规则引用和操作记录。
- 支持一个设备多个点位和多个动作。
- 点位名称、单位、数据类型、读写属性、缩放、偏移、有效范围和精度。
- 点位状态：正常、未初始化、过期、禁用、读取失败、人工接管。
- 型号模板保存一组点位、动作、单位和换算；不包含真实连接地址或凭据。
- 同类设备更换品牌/协议时只更换绑定；业务 ID、规则、历史归属和权限不变。
- 业务 ID 永久稳定；界面默认不暴露内部 ID。

### C. 设备接入与连接管理

#### 通用能力

- 新增、编辑、测试、启停和删除连接。
- 展示连接状态、最近成功通信、错误原因、错误计数和重连状态。
- 只读连接测试与只读诊断，不因测试而写设备。
- 凭据仅用于连接，不进入普通导出、日志或截图。
- 同一连接管理多个点位；添加点位不应意外产生控制动作。
- 通信失败时区分“离线”“配置错误”“超时”“数据无效”。

#### 首批正式协议

- Modbus TCP：地址、站号、寄存器类型、数据格式、轮询、超时、缩放和偏移。
- Modbus RTU：串口、波特率及串口参数；明确单机占用串口和总线冲突。
- MQTT：连接、认证、主题映射、QoS、在线状态与 JSON 载荷提取。
- HTTP：请求地址、认证、轮询、响应字段映射；Webhook 作为主动上报入口。

#### 后续可选协议

OPC UA、BACnet/IP、SNMP、ESPHome、云厂商 API。每种协议必须有真实接入与回读验收后才能标记“支持”。

### D. 点表与批量配置

- 中文 CSV 模板下载、导入预览、逐行错误定位和整批确认。
- 非法类型、重复名称、越界地址、非法缩放等在任何写入前发现。
- 导入失败不留下半批配置；批量操作有结果报告。
- 导出当前点表，供修改后再次导入。
- 批量修改轮询、单位、读写属性和所属分组。
- 从已有设备保存型号模板；用模板批量创建同类设备。
- 模板冲突可选择跳过或更新，但不能静默覆盖。

### E. 实时工作台

- 设备点位数、在线率、自动规则运行数、未处理异常和最近变化。
- 按树层级浏览，也支持按名称、状态、类型搜索。
- 设备卡片/列表显示真实状态、当前值、目标值、单位和更新时间。
- 显示数据是否过期，不把最后缓存值伪装成实时值。
- 收藏常用设备、保存筛选和自定义工作台布局。
- 移动端完成查看、告警处理和授权控制，而不是只能打开桌面页面。

### F. 人工控制与命令可靠性

- 开关、设定值、模式切换等固定动作由点位能力决定。
- 二次确认用于高风险动作；界面明确动作对象、目标值和影响范围。
- 命令状态：待发送、已接受、执行中、已回读、失败、结果未知、超时。
- “已接受”不等于“设备已执行”；有回读时展示实际回读值。
- 请求唯一标识、防止重复提交、串行控制和可配置超时。
- 失败不得伪报成功；通信中断时结果必须标为未知。
- 人工接管只暂停目标点位的自动输出，不禁止人工操作。
- 恢复自动立即按当前有效输入重新评估，并留下记录。
- 支持设备维护模式；维护期间禁止自动输出并明确提示。

### G. 有序决策表与自动化

#### 编辑与运行

- 多输入、同一行多条件 AND、一行多输出顺序执行。
- 从上到下首条命中即停止，支持上下排序和默认不动作行。
- 条件支持 =、≠、>、≥、<、≤；后续增加范围、文本和布尔类型。
- 草稿、发布、启用、停用相互独立。
- 模拟使用当前编辑内容，由真实规则引擎计算，绝不下发。
- 发布前检查空绑定、非法数值、只读目标、跨范围和失效点位。
- 同一命中行不重复执行；版本变化、换绑和恢复自动的语义明确。
- 冷却时间、输入有效期、缺失输入和通信错误时禁止新动作。
- 自动输出和人工命令共享权限、目标校验和操作记录。

#### 管理与排障

- 规则重命名、复制、删除和按项目筛选。
- 草稿与已发布版本对比。
- 发布历史、发布时间、发布人和版本回滚。
- 最近命中行、输入快照、输出结果、失败原因和执行耗时。
- 可查看“哪些规则引用了这个点位”。
- 一个输出被多条规则控制时提示冲突风险。

#### 后续编排

在确有需求时增加延时、持续时间触发、定时计划和节假日日历；不把首版决策表变成自由脚本或流程画布。

### H. 告警与事件中心

- 离线、过期、超范围、通信失败、控制失败、规则错误等内置告警。
- 阈值规则可复用决策表输入能力，但告警与控制生命周期分开。
- 告警等级：提示、重要、紧急；明确是否需确认。
- 告警产生、恢复、确认、指派、关闭全过程留痕。
- 相同问题去重，避免每次轮询生成一条告警。
- 按站点、设备、等级、状态和时间查询。
- 工作台显示未处理数量；已恢复但未确认的问题仍可追踪。
- 通知渠道后续支持邮件、Webhook、短信和企业消息；通知失败需记录。

### I. 历史、趋势与分析

- 数值曲线、开关状态变化和操作事件统一时间轴。
- 时间范围选择、缩放、多个点位对比和数据导出。
- 原始数据与按小时/天聚合数据分开标识。
- 数据缺失、过期和人工修改在图上可解释。
- 保留策略和存储用量可配置；超限时预警而不是静默删除。
- 通用统计：在线时长、告警次数、控制次数和最值。
- 行业能耗、效率和报表由上层业务包提供，不写死进通用底座。

### J. 账号、权限与审计

- 本人账号登录，不使用共享管理员令牌。
- 管理员、实施/运维、操作员、查看者等角色按项目树授权。
- 默认拒绝；用户只能看到授权树中的对象。
- 读、配置、控制、接管、发布、备份等权限分离。
- 用户新增、编辑角色、停用、重置密码；停用后使会话失效。
- 操作审计记录人员、时间、对象、动作、结果和来源；不记录密码或令牌。
- 支持按人、设备、结果和时间检索及导出。
- 权限变更及时生效；不能只隐藏按钮，服务端必须再次校验。
- 公网部署前必须有 HTTPS、密码策略、登录限流和会话撤销验证。

### K. 备份、恢复与升级

- 产品配置导出与完整实例备份明确区分。
- 型号模板、点表和规则可单独导入导出，敏感字段默认不包含。
- 完整备份包含配置、账号哈希、设备密钥、状态和历史；备份文件按敏感数据处理。
- 显示备份时间、版本、大小、内容和校验结果。
- 恢复前预检兼容性与磁盘空间；失败不得破坏现有实例。
- 首版支持已实测的“停止应用后复制完整数据目录”；不冒充在线热备份。
- 升级前提示备份；数据库迁移失败必须停止并保留原数据。
- 明确备份保留策略、恢复责任人和恢复演练记录。

### L. 开放接口与扩展边界

- 产品内不暴露通用节点写入、宿主管控或内部消息总线。
- 对外 API 使用独立应用级授权、范围控制、限流和审计。
- Webhook/API 只提供明确的业务能力，不直接开放任意协议命令。
- 型号模板、协议连接器和业务页面可扩展，但不得改变稳定业务 ID 与规则语义。
- 行业包只增加视图、模板和统计，不复制一套底座。

## 4. 页面信息架构

建议最终只保留六个一级入口：

1. **工作台**：状态、告警、常用设备和最近变化。
2. **设备与点位**：业务树、接入、模板、详情、控制和诊断。
3. **决策表**：编辑、模拟、发布、版本、运行记录。
4. **告警与历史**：告警处理、趋势、事件和数据导出。
5. **交付与维护**：账号权限、交付检查、备份恢复、系统状态。
6. **设置**：实例信息、个人密码和偏好。

协议、寄存器、绑定和调试参数出现在具体任务中，不作为一级工程菜单。

## 5. 优先级与实施阶段

### P0：可管理的通用底座

完成基础 CRUD、移动/删除依赖保护、启停、型号模板、点表导入导出、连接诊断、控制结果状态、规则管理和完整交付检查。

**验收：**非开发人员从空实例完成接入、建模、规则、授权和交付，并能在不修改代码的情况下修正配置。

### P1：可持续运行

完成告警中心、历史趋势、命令可靠性、完整审计、密码/会话管理、备份预检与恢复演练、数据保留和资源监控。

**验收：**设备断线、规则失败、误操作、账号停用和恢复备份都有可观察、可解释、可追踪的结果。

### P2：规模化与生态

增加 MQTT/HTTP 等协议、批量项目复制、开放 API、通知渠道、高级计划、行业包和边缘同步。

**验收：**每种能力独立做协议、权限、故障和恢复测试；没有通过验收的功能不标记为正式支持。

## 6. 每阶段必须通过的通用门槛

- **真实操作：**浏览器完成任务，而非只编译或只测函数。
- **真实协议：**模拟设备验证报文；真实设备仍需现场验收。
- **失败路径：**断线、超时、错误输入、重复提交、权限不足和恢复均必须测试。
- **数据安全：**不泄露密码、令牌、连接凭据；服务端默认拒绝。
- **可恢复：**重启、升级、备份恢复和失败回滚有明确验证。
- **易用性：**非技术人员不需要 YAML、代码、内部 ID、服务名或工程后台。
- **交付边界：**测试变量、模拟协议、自动化脚本不冒充真实物理设备或独立用户验收。

## 7. 明确的非目标

- 不做低代码流程画布、自由脚本平台或通用应用开发平台。
- 不为了支持更多协议而牺牲统一的业务模型和控制安全。
- 不在首版堆叠数字孪生、AI 预测、复杂 BI、工单、视频和资产管理。
- 不用“功能已创建页面”代替“用户任务已完成”。
- 不用单元测试、截图或模拟器宣称真实硬件与独立用户已经验收。

最终完成标准：**用户能接入、能看懂、能控制、能自动运行、能排障、能授权、能恢复；实施者不需要改源码，维护者不需要猜系统内部结构。**
