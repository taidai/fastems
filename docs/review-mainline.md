## 四、首版真缺口（3 件事，必须现在定案 + 补）

### ① PCC 反馈点绑定（TOP-02 / OBJ-01 的首版子集）——闭环第一硬伤
- **现状**：`AntiReverse(pccKW)` 的 PCC 功率是空参数，`PointTypeSiteTarget/PlantTarget` 只有目标值，**没有"PCC 功率从哪个点位读 + 正负方向 + 有效期"的领域模型**。防逆流/需量无法真正闭环。
- **定案建议**：Site/Plant 下新增 PCC 反馈绑定：`{ meterPointID, direction(购电为正), maxAge, upperLimit/lowerLimit }`；`AntiReverse`/`PeakShaving` 从该绑定读实测，不再吃空参数。
- **验收**：T06（PCC 闭环）、T19 的单 PCC 子集。

### ② 柜体运行状态机（CTL-01）——可控/互锁落地基础
- **现状**：只有命令状态机（command.State），**没有柜体运行状态机**（启动/待机/运行/停机/故障/检修的转移 + 守卫 + 谁确认）。
- **定案建议**：EnergyUnit 增加运行状态字段 + 转移表（触发/守卫/反馈点/超时/可用控制权）；互锁（Q9）挂在状态机上，故障态禁止自动调度。
- **验收**：T11（保护联锁与复归）。

### ③ 统一追溯时间线（OBS-01）——可解释性最后一块
- **现状**：审计/命令/分配各有记录，**缺"同一关联 ID 串起 目标→能力→分配→命令→实测"的可回放时间线**。
- **定案建议**：每次调度生成 `dispatchID`，写入能力快照/分配/命令/审计共用该 ID；值班员事件页按 dispatchID 复盘。
- **验收**：T18（值班员复盘）。
