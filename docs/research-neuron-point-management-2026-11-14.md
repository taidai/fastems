# FastIOT 点位采集管理如何借鉴 Neuron

日期：2026-11-14。范围：只研究 Neuron 的接入与点位管理；不研究其他对标产品，不安装或运行产品，不修改现有规格。本文是文档研究，不是产品实测或实现完成声明。

## 1. 决策摘要

**建议借鉴的是一条可完成的工程操作路径，而不是再添一组功能菜单：选协议与连接 → 建立采集组与点位 → 批量复用 → 看错误和读值 → 验证获准写入。** Neuron 的官方页面把设备、组、点位与数据监控串在一起，且将运行状态与连接状态分开。[S1][S2][S3][S4]

**FastIOT 的主要需求已经写进规格。** 现有细则已要求 CSV 逐行校验、原始／业务值、编码与缩放、局部质量、时间来源、独立设备复制、稳定引用；主规格已要求未保存／已保存未生效／已生效反馈。更有价值的是给 T27/T33 补具体反例，而非重新定义点位工作台。[F1][F2]

**最重要的边界：当前 `latest` 页面中的 Neuron 不能直接当成旧版 Neuron。** 当前许可说明明确写作 “EMQX Neuron (formerly NeuronEX)”；发布历史顶部已到 v4.0.2。下文涉及免费额度、驱动和菜单的事实限定于本次读到的文档，不倒推旧版 Neuron，也不套用到 FastIOT 的商业划分。[S5][S6]

**尚不能证明的两件事：** 任意点位／连接配置是否能无中断热改，以及监控值的时间戳究竟来自设备、采集还是转发。已读页面未给出足够契约；不能因有编辑按钮或时间字段需求，就宣称 Neuron 已满足。[S1][S2][S4][S7]

**待验证：** 旧版 Neuron（包括其具体发行版）与 NeuronEX 的完整产品矩阵、旧版免费驱动清单、名称切换的准确版本，以及旧项目对当前版本的兼容性。本次没有取得这些历史版本的完整依据，不给出“旧 Neuron＝当前免费版”或“NeuronEX＝仅多了商业驱动”的简化结论。[S5][S6]

### 3.2 当前文档中的免费／商业边界，不做许可推论

- **事实：** 当前内置免费额度为 30 个数据 tag、无到期时间；试用为 1,000 tag、15 天；商业容量按购买额度。免费条件下数据处理规则为测试用途，每条规则运行 60 分钟后停止。这里只用于解释产品范围，不建议 FastIOT 采用按点收费或同样的到期行为。[S5]
- **事实：** 免费范围内列有 Modbus、OPC UA、Siemens/Mitsubishi PLC、EtherNet/IP 等协议；Fanuc Focas Ethernet 与 Mitsubishi CNC 被明确排除。**Mitsubishi PLC 不等于 Mitsubishi CNC。** 商业模块要看实例的实际授权，不以菜单可见或安装包包含来判断可用。[S5]
- **事实：** v3.9.0 发布说明写标准安装包包含全部 CNC 驱动插件；这与免费范围排除 CNC 并不矛盾，“已打包”不是“已授权”。[S5][S6]
- **边界：** 本文没有审查代码许可证、再分发或商用法律条件；不作“可以直接复用代码”“所有驱动免费／开源”等结论，也不改变 FastIOT 的既定许可设计。

## 4. 沿实际操作路径看可借鉴的细节

### 4.1 接入一台设备：先明确节点，再解释状态

**事实路径：** `Data Collection → South Devices → Add Device`，输入唯一名称并选择协议驱动；创建后进入该节点的 `Device Configuration` 填写协议连接参数，再进入 `Group List`。官方将一个 driver node 描述为对应一台设备或一组设备，因此不能把“驱动节点”机械等同于业务设备实例。[S1]

**事实结构：** 创建节点时选择协议驱动；节点下创建 group，组中建立 tag。组同时是采集与北向订阅的边界，北向消费者订阅组。该技术分组不自动等于 FastIOT 的业务 Group、Area 或 Unit。[S1][S2] 后一句是对象映射建议；FastIOT 的业务对象定义见主规格。[F2]

**事实状态：** Neuron 分别显示 `Init / Ready / Running / Stopped` 和 `Connected / Disconnected`；`Running` 表示按组间隔发起读取，`Connected` 表示通信与读取响应正常。新节点尚无 tag 时保持断开；不能把这一状态一律解释为线缆或站号故障。节点开关控制启动／停止采集，文档说明关闭会断开连接。[S1]

**建议：** FastIOT 保留自己的连接—设备—Profile—点位身份，在现有设备配置处解释“没有可读点”“未启动”“无响应”“局部点错”；不照搬一层用户必须管理的驱动节点，也不新增业务分组体系。现有细则已经要求这类分因解释。[F1]

### 4.2 建组、加点：轮询、变化上报与界面刷新不是一个承诺

**事实路径：** 在节点内 `Create Group`，填写名称与以毫秒为单位的 interval；进入 `Tag List → Add Tag`，配置名称、属性、类型及协议地址。组页面将 interval 描述为轮询与上报间隔，组内点按共同节奏采集并组成上报消息。[S2]

**事实：** `read` 使点参与周期读取；`write` 允许通过相应入口写入；`subscribe` 用于值变化触发发布，**不会因此停止设备周期轮询**。本页没有给出通用的“采样周期与上报周期可分别独立设置”契约，也没有完整解释所有属性组合的消息行为。[S2]

**待验证：** 协议原生订阅、变化上报、北向传输和界面刷新各自的时间关系；浏览器刷新频率是否可配；每个上报值是否携带原始采样时间。不能从“组 interval”或“值变才发”推导这些结论。[S2][S4]

**建议：** FastIOT 在原采集参数处讲清自己已实现的采集周期与有效期；如果已有独立上报或刷新策略，再标明它们不改变采样事实，不因此引入新北向协议或更多配置项。原规格已要求采集周期、有效期和时间来源可理解，但没有明确展开这些节奏之间的区别。[F1]

### 4.3 调对一个点：地址、类型和转换各有责任

**事实：** tag 类型与地址依赖具体驱动；组／点页面使用 `1!40001` 举例，表示 Modbus 从站 1 的保持寄存器 40001。该语法是示例，不是所有驱动的通用地址格式。加点界面的直接地址测试，文档限定为 Modbus TCP，不能据此声称 RTU 有相同测试入口。[S2]

**事实：** 页面分别说明乘数和偏移，并给出 `device value × decimal = reported value`、`device value + bias = reported value`。转换要求读属性；bias 还限制为非可写点及相应数值类型。工程单位是标签，不自动转换数值。[S2]

**重要限制：** 上述两个单独公式不能证明乘数与偏移共存时的计算顺序，也不能证明写入侧自动执行逆变换。本文不补写一个未证实的统一公式。[S2]

**事实：** Excel 模板页把 `precision` 解释为读值乘数，把 `decimal` 解释为 float/double 精度设置；组／点页的转换描述则使用 decimal 表述乘数。两页字段语境有差异，不能按英文列名猜含义或未经版本核对就直接转换点表。[S2][S3]

**建议：** FastIOT 使用已有 Profile 语义说明编码、字／字节序、缩放、偏移和单位，在原始值旁显示实际换算结果。数据类型、数值换算与显示小数位分开验收；若支持可写工程值，另核对其已声明写入映射，不借 Neuron 文档推定逆变换成立。原规格已有这些基础要求。[F1]

### 4.4 做一批点、复制到第二台设备、再导出

**事实路径：** `South Devices → Group List`，在 `Import` 菜单下载 Excel 模板，填写后点击 `Import` 选文件；在组列表勾选目标组或全选后 `Export`，得到包含组及组内点的 Excel 文件。模板包含 group、name、address、attribute、type、description、precision、decimal；填入不存在的 group 名会创建该组。[S3]

**事实：** 当前发布历史说明 v3.2.0 已有南向配置复制和导入导出；v4.0.0 又新增 CSV 点位导入导出。但这两条版本记录不提供本次可逐步复核的完整复制／CSV 界面路径，本文不编造菜单名称。[S6]

**待验证：** 混合好坏行是否部分导入、重复名称处理、导入事务边界、错误定位粒度、导出是否包含所有转换与单位、运行中能否导入，以及复制是否带入现场秘密／连接参数。模板下载成功或导出文件存在不能证明这些行为。[S3][S6]

**建议：** FastIOT 沿用现有 CSV 与 Profile 路径即可；不因 Neuron 有 Excel 就增加一种必须维护的格式。最小借鉴是“有可填写样例—按设备批量操作—明确结果—可往返验证”；FastIOT 现有逐行预览、秘密隔离与稳定引用要求比已读 Neuron 批量页的说明更明确。[F1]

### 4.5 定位错误、确认数据，再核对写入

**事实路径：** `Data Collection → Data Monitoring`，选择 `South device` 和 `Group`，用名称搜索，或开启 `Show error tags only` 找采集失败点。对具备写属性且设备地址允许写入的点，点击 `Write`，选择是否按十六进制输入，填写值并 `Submit`；官方建议查看后续读值，并在设备／模拟器侧核对。[S4]

**事实：** 错误码页能区分非法配置／类型／地址与读写通信错误，例如 2004（节点配置无效）、2204（不支持的 tag 类型）、2205（地址格式无效）、3000/3001（读／写失败）、3002（驱动未连接）、3003/3004（不允许读／写）、3007（驱动点类型不匹配）。这些是诊断分类依据，不等于完整点位质量模型。[S7]

**待验证：** 监控页是否同时呈现原始／工程值、最后成功时间、当前质量、保留的旧值和设备时间来源；断线后旧值怎样标记；错误码与每个值的对应结构；报文与耗时的可见程度。已读页面没有足够证据将这些标为支持。[S1][S4][S7]

**建议：** 不照搬“数值变了才说明采集成功”的粗略判断；恒定压力也可能是新鲜有效的观测。FastIOT 应按本身已声明的观测时间与质量判断。写操作的页面成功、输入回填、协议应答也不能冒充设备动作反馈；这不是 Neuron 已验证的强保证，而是 FastIOT 原有 T04/T31 的要求。[F1][F2]

### 4.6 运行中修改：已知能力与未知生效语义分开

| 对象／操作 | 已核实事实 | 仍不能宣称 |
| --- | --- | --- |
| 连接／节点 | 有 Device Configuration、Edit Device 和运行开关；开关关闭会断开连接 | 保存连接参数是否立即重连、是否必须先停节点、是否影响其他节点。[S1] |
| 点位／组编辑 | v3.9.0 支持 tag 名称编辑；v3.9.1 修复重命名 tag 后保存的问题；v3.5.5 有修改 OPC UA 组名相关崩溃修复 | 所有驱动／字段均可无中断热改；重命名自动保持所有外部引用。[S6] |
| 运行状态限制 | 错误码包含 2007（节点运行中）、2008（未运行）、2009（已停止）、2013（不允许更新节点） | 单靠错误码就推导“运行中一律不许编辑”，或判断究竟哪个 API／字段触发它。[S7] |
| 批量导入 | 有文档化导入入口及版本化 CSV 支持 | 导入原子生效、失败自动回滚、不中断采集或完全不影响控制。[S3][S6] |

**结论／建议：** 运行中配置变更的通用行为本次未核实，不把“热更新”列为 Neuron 优势。FastIOT 应执行自己已确定的未保存／已保存未生效／已生效反馈，并在原编辑处说明某次应用是否需要暂停采集；不能为补证据另建升级、恢复或审批流程。[F2]

## 5. 最多五项规格建议——只补原操作和原验收

### 建议 1：用一次“两设备点表往返”检验批量复用，而非再新增模板模块

- **用户价值：** 点表复用真的减少重复录入，不把第二台设备误绑到第一台。
- **依据与现状：** Neuron 有模板填写与组级导入导出路径；FastIOT 已覆盖 CSV、复制、现场差异、逐行错误、稳定引用和往返保真，不需要重复新增需求。[S3][F1]
- **最小采用：** 在既有导入／复制操作中使用同一份小点表，包含正常点、重复身份、坏地址、非法类型及一个已被画面引用的点；复制时显式填写第二台设备差异，导出后再导入核对已声明语义。保持现有 CSV 范围。
- **反例验收：** 坏行不能显示全部成功；重复标识不能静默覆盖；复制后的 A/B 不串读串写；秘密不进入导出；地址可变化但模型／画面仍引用正确稳定身份。
- **现有 T 对应：** **T33** 主验；**T27、T19、T28** 复用。属于已覆盖要求的具体化，不新增编号。[F1][F2]

### 建议 2：把“解码—换算—显示”分开，避免小数位掩盖十倍错误

- **用户价值：** 工程人员能在一个点上解释为何数值不对，不靠猜单位或反复试倍率。
- **依据与现状：** Neuron 的地址／类型、乘数／偏移、精度与单位存在不同语义；其模板列名也不能脱离版本解释。FastIOT 已要求编码、字序、缩放、偏移、单位和原始／业务值对照。[S2][S3][F1]
- **最小采用：** 在现有点位诊断处列出使用中的地址与编码、原始解码值、转换参数、业务值、显示精度和单位；只展示当前协议／Profile 实际适用的字段。明确公式次序是 FastIOT 的契约，不复写未经核验的 Neuron组合公式。
- **反例验收：** 原值 1234、倍率 0.1 的业务值应为 123.4；改显示小数位不改变底层业务值。错字序／错类型不能仅靠倍率“修好”；若开放可写工程值，必须核对实际写出的原始值，不能假设读换算自动可逆。
- **现有 T 对应：** **T27、T33** 主验，**T28、T04** 复核读写映射与结果。基础已覆盖，需补精度与数值转换不混淆的反例。[F1][F2]

### 建议 3：只解释真实存在的采集、上报与刷新节奏，不强制新增采集组

- **用户价值：** 避免误以为画面更新快就采样快，或值没变就没采到。
- **依据与现状：** Neuron 组 interval 与 subscribe 属性分别涉及周期采集／上报和变化发布；变化发布不代表停止轮询。FastIOT 已要求采集周期、有效期与时间来源，但可以更明确节奏含义。[S2][F1]
- **最小采用：** 原采集参数提示中说明周期的实际作用；数据处保留已有时间来源与质量。仅在已实现独立上报／刷新时解释它们，不据此添加协议、采集组必填对象、历史存储策略或新的参数面板。
- **反例验收：** 用恒定值连续成功读取，仍显示新鲜有效；仅刷新页面不能刷新“最近成功采集时间”；若已有变化上报，未上报不能被误判为设备离线，旧缓存也不能伪装新样本。有效期按已声明的时间来源判定。
- **现有 T 对应：** **T27、T33**；引用现有时间／质量要求，不把 Neuron 的 30 ms 或 100 ms 写成 FastIOT 性能门槛。[F1][F2]

### 建议 4：把节点状态、点位质量与命令结果分三层展示

- **用户价值：** 一眼判断是没配点、没启动、链路断、单点地址错还是写入被拒，避免“设备在线所以都能控制”。
- **依据与现状：** Neuron 分开运行／连接状态，并可过滤错误点与区分读写错误；FastIOT 已进一步要求逐点质量、最近成功时间、局部失效及真实控制反馈。[S1][S4][S7][F1][F2]
- **最小采用：** 在现有设备和点位页显示可解释的状态／错误原因，保留当前值与最后有效观测的区别；已有诊断入口定位同一设备和点位。工程写入仍走既有授权与命令路径，不从 Neuron 的 Write 按钮引入任意寄存器旁路。
- **反例验收：** 无 tag 不冒充通信故障；压力过期但反馈正常时不能全绿或全清空；断线旧值不补零、不刷新时间；只读写入应拒绝；页面提交成功或协议应答而无独立有效反馈时，不得显示设备已运行。
- **现有 T 对应：** **T27、T33** 主验，**T03、T04、T31** 复用。现有规格已基本覆盖，无需另建健康中心。[F1][F2]

### 建议 5：把运行中应用配置的边界写在原保存／应用操作上

- **用户价值：** 修改地址、倍率或导入点表时知道当前现场究竟使用哪份配置，不误以为保存就是生效。
- **依据与现状：** Neuron 的已读文档不足以保证通用热更新；FastIOT 主规格已经要求草稿／生效分离、失败保留输入、明确应用前不改变现场逻辑。[S1][S3][S6][S7][F2]
- **最小采用：** 对已支持的连接／点位修改，原页面反馈是否保存、是否应用、失败原因，以及本次是否需要暂停采集；重用现有应用入口，不增版本发布工作台或回滚中心。不承诺所有修改都不中断。
- **反例验收：** 运行配置 A 时编辑并保存倍率或地址 B，明确应用前仍按 A 工作；应用失败不得显示 B 已生效，现场值也不能混用未标识的 A/B；恢复采集不能重发旧命令，修改被引用点不能静默破坏引用。
- **现有 T 对应：** **T33、T26、T27**；**T13** 仅复用已有草稿隔离原则，不把规则专用测试直接当作点位已通过的证据。现有原则已覆盖，需补点位场景。[F1][F2]

## 6. 仍需验证的最小清单与停止线

这些是本次证据限制，不是本轮要求新增的任务流程：

1. **指定版本的导入行为：** CSV／Excel 的确切 schema、重复行／错误行结果、完整往返及现场参数复制范围。目前只有 Excel 操作说明和 CSV 发布条目。[S3][S6]
2. **运行中配置契约：** 同一指定版本、指定驱动下，连接、地址、类型、组周期、重命名和导入分别是否需停采、何时生效、失败后实际使用什么。不能用错误码或某次修复替代验证。[S1][S6][S7]
3. **数据时效及写入证明：** 时间字段的来源、断线缓存与逐点质量、写确认／后续读取／独立设备反馈的边界。当前监控说明只足以证明存在查看和写值路径。[S4][S7]
4. **旧 Neuron 与当前“原 NeuronEX”的历史边界：** 如后续真的选型，需先指定产品包与版本再核对驱动授权；本次不对未读的旧版本补结论。[S5][S6]

**停止线：** 本文不引入新流程、新技术栈、新协议承诺、许可设计或性能指标；不建议把 Neuron 的技术 group 当业务对象，不把模板文件当完整物模型，不把写值按钮当业务命令确认。上述五项仅作为现有规格的收敛建议，规格与实现均未在本次修改。
