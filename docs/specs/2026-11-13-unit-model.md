# FastIOT 通用 Unit 与 EMS 专业模型

状态：按用户要求补充的本地规格，未同步 GitHub，未迁移代码或已有数据。本文是[产品总规格](2026-11-13-open-scada-paid-ems.md)的建模细则，不要求用户学习内部控制阶段。

## 1. 平台提供 Unit，行业包定义它的业务含义

本文承接[通用物模型](2026-11-13-generic-thing-model.md)：Site 表达现场，Area 表达组织容器，Group 表达横向集合，Unit 表达功能对象。Plant、EnergyUnit 和 ResourceGroup 是 EMS 专业类型，不是强制所有项目采用的固定层级。本文进一步细化 Unit 组合及 EMS 能力与目标语义。

**Unit（业务单元）**是具有独立业务身份、对外属性／命令／事件和成员绑定的功能对象。它可以组合一台或多台 Device；普通 Device 也可直接用于画面和逻辑，不强制创建 Unit。

**EnergyUnit**是满足 EMS 能源模型与约束的 Unit，用来表达最小可独立受控的能源能力。不是把所有 Unit 都附上 SOC，也不是仅把现有 energyUnit 类型全局改名。

| 对象 | 主要含义 | 例子 |
| --- | --- | --- |
| 连接／Channel | 与现场通信的路径 | 一条 RTU 总线 |
| Device | 有独立身份与厂商映射的设备实例 | 变频器、压力变送器、PCS、BMS |
| Point | 明确来源或只读计算的数据项 | 压力、运行反馈、功率设定 |
| Unit | 对外提供完整业务含义的功能对象 | 供水单元、储能单元 |
| Unit 模板 | 可复用的成员角色及对外业务定义 | 单泵供水模板、储能单元模板 |
| EnergyUnit | EMS 专业化 Unit | 由 PCS、BMS 和相关测量组成的储能控制单元 |
| ResourceGroup | EMS 中共享分配约束的资源关系 | 同站跨电站的有功资源组 |

平台保留可配置的业务组织结构，不要求所有项目都按 Site／Plant／ResourceGroup／EnergyUnit 排列。Site／Plant 上的能源目标与约束、PCC 与有功组规则属于 EMS 专业语义；普通地点组织不必带能源字段。展示分组不是可控制 Unit，更不会自动广播命令。

### 供水与储能的共同部分、不同部分

- 供水 Unit 可绑定驱动设备、压力与液位测量，对外提供运行状态、压力及获准启停。它不需要额定 kWh、SOC 或 Plant。
- 储能 EnergyUnit 可绑定 PCS、BMS、电表及实际需要的辅助设备，对外提供有功功率、SOC、状态、可用充放功率及获准操作。
- 单独的压力传感器直接作为 Device 使用；不为展示一个数值制造空 Unit。
- 两个 Device 关联到同一 Unit，不等于自动获得“整体启动”。组合属性和动作必须明确声明或引用已有规则／状态机能力。

## 2. Unit 模板与实例必须表达什么

### 通用定义

- 稳定身份、业务类型、名称与组织归属；不以设备型号、地址或显示路径作为唯一业务身份。
- 对外属性、命令和事件的类型、单位、用途与语义；画面、规则和状态机可以引用 Unit 成员，也可以直接引用 Device 成员。
- 成员角色及必需／可选条件，例如驱动、压力测量、功率执行、BMS 允许信号和功率测量；实例将角色绑定到实际 Device／Point。
- 属性来源、只读聚合及质量规则；禁止循环引用、重复计算和用缺省零伪装有效值。
- 对外操作如何映射到成员动作，需要哪些条件及反馈。多设备过程复用已有声明式规则／状态机；不增加自由脚本或自动推断控制顺序。
- 模板默认值与实例覆盖清楚，公共定义可复用，现场连接和秘密独立。

### 成员关系不等于控制所有权

只读测量可被多个业务视图或 Unit 引用；每个统计或分配过程必须按真实来源去重。一个物理控制器可能承载多个不同目标，不能粗暴地用“整台 Device 只能归一个 Unit”替代目标级判断。

同一最终受控目标不能通过多个 Unit 获得相互独立的写入所有权。成员动作、直接设备操作和上层目标遵守同一权限与控制约束。多处展示不增加写权限，组合操作不能越过成员级保护。

为首批供水与能源样板提供上述必要组合能力；暂不因此增加任意深度的 Unit 嵌套、自动成员发现或通用编程框架。

### 使用与换品牌

交付人员选择 Unit 模板，绑定成员角色，补实例参数，模拟对外操作，再让 AI 使用其模型生成画面。配置不完整的草稿可以保存并继续制作，但受缺项影响的真实操作不可用；缺项就在当前编辑位置指出，不建立独立检查流程。

厂商变化优先影响 Device/Profile 及成员绑定；能力语义等价时，Unit 对外标识、规则引用及画面定义保持稳定。语义不等价、必需反馈缺失或物理条件改变时必须明确指出，不能保证任意品牌无缝替换。

## 3. 平台通用能力契约

Unit 的支持项、参数语义、当前可用性、来源时间和不可用原因属于通用模型描述；鉴权状态不改变型号支持项。具体数值含义与计算规则由模板或行业包提供。

对于有量化资源目标的 Unit，区分以下三种口径；只有离散启停的 Unit 可只表达支持项、当前允许状态与条件，不强行套数值能力。

| 口径 | 回答的问题 | 不能冒充什么 |
| --- | --- | --- |
| 额定能力 | 这个单元按型号及明确实例参数具备什么设计范围？ | 不等于当前在线、可控或可持续提供的能力 |
| 实时允许能力 | 在当前设备观测、状态、有效性和保护条件下，允许做多少？ | 不等于已分配目标，也不由登录用户权限改写型号额定值 |
| 本次可分配能力 | 在实时允许范围内，考虑上层／组约束、当前控制参与资格及已占用资源后，这次目标可使用多少？ | 不等于最终执行值或实际反馈 |

平台统一这些描述的身份、单位、方向、时效和来源；不内置适用于所有行业的求和公式。行业逻辑负责哪些能力可相加、哪些应受共同条件限制。量纲不同或语义不等价时不可直接汇总。

必需输入缺失、坏值或过期时，不把额定值当作实时可用值。可选测量异常只影响依赖它的展示或动作，不无条件让全部属性失效。没有反馈不能把“支持此操作”写成“操作已成功”。

## 4. EMS 的层级目标与约束

这是能源业务行为，不要求把每层实现成单独进程或用户菜单。

| 对象／关系 | 用户定义的内容 | 必须得到的结果 |
| --- | --- | --- |
| Site | 站级目标及约束、所属 Plant、相关 PCC | 在站级约束内形成可满足的电站目标，说明未满足部分 |
| Plant | 本电站目标／限制、关联能源单元与反馈 | 将允许目标分到实际可参与的 EnergyUnit，不能超过上层或本地约束 |
| ResourceGroup | 同 Site 的成员、共享限值和参与规则，可跨 Plant | 对相关成员施加共同约束，不成为另一条独立设备写口 |
| EnergyUnit | 标准能源能力、成员映射和允许条件 | 在本单元能力内执行分配目标，并说明受限或不可参与原因 |
| Device／Point | 厂商命令、数据和反馈映射 | 执行被允许的具体动作，返回实际观测和结果 |

业务归属树与分配关系分开：跨 Plant 的 ResourceGroup 不是强制插入树中的父节点。同一个 EnergyUnit 仅属一个有功组；同一资源能力只计一次，各 PCC 的约束分别生效。

层级分配必须同时满足相关 Site、Plant、ResourceGroup、EnergyUnit 和 PCC 条件，不能一层分配完后又被另一层无解释覆盖。不能满足目标时保留原请求、可满足目标和缺口，说明造成限制的对象，不虚构执行结果。

**示例，不是算法或功率参数定案：** 站点请求 300 kW，应用全部当前能力与约束后只能满足 240 kW，应显示 60 kW 缺口及原因；没有后续设备反馈，不能宣称已实际输出 240 kW。两个电站如何分得这 240 kW，取决于明确选择的分配规则，而不是本示例指定。

### 首版目标协调与分配（已确认）

2026-11-14 用户最终确认。普通控制来源先遵守[活动自动来源契约](2026-11-13-core-capabilities.md#活动自动来源与控制冲突已确认)；以下是 EMS 内部业务协调，不作为普通 SCADA 的必填能力或通用压力／启停分配算法。

**目标与约束分工：** 由一个明确活动业务目标来源给出期望，例如已选择的时段计划；需量、防逆流按声明的作用方向和场景提出调节要求或限制，不把各策略功率不分含义地相加。设备能力、SOC／BMS、资源组及逐 PCC 等硬约束共同限制可执行范围。在可行范围内，需量调节要求优先于普通经济计划，再尽量接近原计划；不得为满足业务目标突破硬限制。

**同类资源分配：** 适用的同类储能按本次可分配能力比例分配，采用同方向且允许自动参与的有效能力，不使用额定 kWh 作为瞬时功率权重。当前参与条件、共享限制、方向、爬坡及其他已声明约束同时有效；不能将简单比例结果直接当作最终可下发结果。共享额度只使用一次，受限后的剩余需求继续分给其他仍有能力且获准参与的资源；所有可用资源仍不足，则保留缺口，不超限或重复计量。

**部分人工接管：** 自动逻辑不再给已接管资源分配目标，也不暗中将其切回自动；在剩余自动资源能力内重新分配并报告不足。人工资源实际功率仍可进入对应 PCC 的真实测量：若目标是自动资源出力总量，按该范围显示缺口；若目标是 PCC 净功率要求，按最新 PCC 实测计算剩余调节需求，不能重复补偿已计入的人工出力。

**光储充按作用方向协调：**

| 业务目的 | 首版明确次序 | 不能采取的替代行为 |
| --- | --- | --- |
| 降低购电／满足需量调节 | 先用可用储能放电，不足时在设备支持及项目获准的服务范围内减少充电负荷 | 减少光伏发电通常增加净购电，不能以此补降低购电缺口；不能擅自突破充电服务限制 |
| 抑制反送 | 先用允许的储能充电，再用实际可用且获准增加的充电负荷，仍不足时对支持且获准的光伏限发 | 没有车辆需求不虚构消纳能力，不支持限发不假称已解决反送，不越过其他 PCC 或设备约束 |

上述次序始终受实际 PCC 作用关系、设备能力、SOC、质量及项目约束限制；不足时解释剩余缺口，并执行已声明的场景保护，不添加未获准动作或任意优化器。

#### 确定输入／输出的验收例子

以下数值是测试输入，不是现场默认参数或性能保证；实际输出须另有设备反馈。示例均假设所述方向明确、数据有效且除所列约束外无其他限制。

| 子场景 | 输入与条件 | 必须得到的目标／结果 |
| --- | --- | --- |
| T37-A 需量与经济计划 | 计划放电 20 kW；需量策略已由有效窗口计算出需至少放电 50 kW；可用能力 80 kW | 协调目标为 50 kW，不是 70 kW；若硬限制改为最多 40，则提出可行的 40，并报告需量调节还差 10，不能宣称需量已达标 |
| T37-B 同类比例与总缺口 | 同方向自动储能 A 可分配 80、B 40 kW，总目标 90；再改目标为 150 | 前者 A＝60、B＝30；后者 A＝80、B＝40，总缺口 30；额定能量不替代当前功率能力 |
| T37-C 共享额度与剩余需求 | A 能力 80、B 40 kW，但两者共同上限 60；独立 C 能力 60；总目标 120，再改为 150 | A、B 共同只用 60，分为 40、20，C 分 60；目标 150 时仍可满足 120、缺口 30；不得各成员重复使用共享额度或只在页面修饰超限总数 |
| T37-D 人工资源与目标口径 | 自动资源目标放电 90 kW，A 被接管，只剩 B 可自动分配 40；另以 PCC 净目标重测 | 自动资源口径最多分 B 40、缺口 50，不对 A 发自动目标；PCC 口径依据最新实测重新计算剩余需求，不遗漏人工实测或重复补偿 |
| T37-E 降低购电的资源方向 | 储能能力不足，存在可减充电负荷和光伏，逐项设置支持／授权／服务限制 | 先储能放电，再在允许范围减少充电；不得减少光伏来补降低购电缺口；受限时明确不足及原因 |
| T37-F 反送与真实可用能力 | 有反送调节需求，逐项设置储能充电、充电负荷接纳及光伏限发能力 | 按充储能、增加获准实际充电负荷、必要时光伏限发的顺序；无需求／无能力／无授权的资源不被虚构参与，未满足时解释缺口及已声明保护 |

验收还须核对原目标、协调目标、分配结果、实际提交和实测彼此可区分；每个 PCC 约束独立生效，局部反送不由全站净额掩盖。保护参数、目标有效性及设备失效行为仍须按具体样板声明和验证；本定案不承诺任意约束组合优化、自动备用来源接替或未支持的行业算法。

## 5. EMS 的三种能力如何计算和展示

- **额定**：从设备 Profile 与明确实例参数得到，分清 kW、kWh、AC／DC 口径与充／放方向。额定能量不直接当作瞬时功率权重。
- **实时允许**：按实际绑定的 BMS 允许信号、SOC、温度、在线状态、时效及场景保护约束得出；充电与放电分别限制。具体组合公式由能源模型声明，不为所有设备写一个无条件默认公式。
- **本次可分配**：在实时允许能力内，应用站／电站／组／PCC 限制以及自动／人工接管、检修等参与条件，说明此次可用于目标分配的范围。限制是共同约束时不能对每个成员重复全额使用。
- 功率与可持续能量分别表达；需要评估时段可行性时使用有效能量、SOC 和时长，不只看铭牌功率，也不把能量不足隐藏为无限可持续出力。
- 能力计算供目标分配使用；新遥测更新能力。不是先发完命令再补算“允许能力”。显示额定值、当前允许值、当前目标与实际值时标清口径；诊断按需展开，不做能力计算运维中心。

## 6. EMS 多设备组合规则

| 成员角色 | 常见提供内容 | 组合时必须明确 |
| --- | --- | --- |
| PCS／执行设备 | 可执行功率或启停、模式及反馈 | 实际命令目标、方向、编码／分辨率、设定确认和实测来源 |
| BMS | SOC、允许充放电、温度／故障等状态 | 哪些是该场景必需输入、多久有效、失效影响哪些方向／动作 |
| 单元电表／PCC 电表 | 单元或并网点实际功率、方向和能量观测 | 表计角色与位置，哪些用于单元观测、哪些用于并网反馈；不能重复累计 |
| 辅助设备 | 实际接入的温控、消防或 IO 状态 | 只读提示、互锁输入或可控动作的明确区别；不因挂载设备就假定支持所有联动 |

上述为角色示例，不意味着每个现场必须增加全部硬件或已支持所有消防／温控协议。模板声明必需和可选角色，并允许在语义等价时使用合适的现有观测来源。

一个 Unit 内有多个功率执行成员时，目标拆解和能力汇总须有明确定义，不默认给每台都写同一个总目标。单位、方向、数据新鲜度、共享资源及成员控制权均要核对。

部分成员不可用时，应说明哪些属性仍可用、哪些能力受限、哪些动作被拒绝或结果未知；不能将部分成功写成整单元成功。多成员动作顺序与失败处理复用声明式规则／状态机并按场景定义；重发仅复用[能力细则 §4](2026-11-13-core-capabilities.md#已确认同一次请求内的受控重发)的命令声明、同一请求窗口及目标回读，不隐式重开失败／未知请求，不将已成功成员整组无条件重做，也不自动产生危险的反向动作。

| T38 | 能力口径与时效 | 区分额定、实时允许和本次可分配能力；必需观测缺失／过期不回落成额定可用，充放方向和功率／能量不混用；当前目标和实际结果不冒充能力 |
| T39 | 多设备组合与成员异常 | 角色绑定清楚，多执行成员不重复领取总目标；可选测量失效不抹去其他正常数据，必需输入失效按声明限制能力；共享测量不重复累计，多个 Unit 不获得同一目标的独立写权；换等价 Profile 保持 Unit 业务引用 |

T36 在非能源样板验证通用层；T37–T39 在能源样板验证专业行为。设备与通信的模拟／物理／真机证据仍分开，所有示例与规格补充都不是已经完成的验收。

## 8. 不随通用化带入的范围

不把能源 kW／SOC／PCC 强加给通用 Unit；不重新引入检查、升级恢复、加入 EMS 流程；不增加 OpenHAB 兼容层、未确认协议、云端跨站控制或任意优化算法。通用化不是机械改名，也不是在本轮直接修改存储节点类型。
