# FastIOT 通用物模型：从现场组织到设备能力

状态：本地规格补充，未同步 GitHub，未实现代码或数据迁移。依据用户提供的三张 EMS 图提取可复用结构，并遵守[产品总规格](2026-11-13-open-scada-paid-ems.md)的当前范围。

**目标：同一套平台模型既能表达泵房，也能表达光储充；行业包补业务语义，不另造一套接入与运行对象。** 下列概念不是建表、菜单或独立进程清单。

## 1. 从三张图保留什么、泛化什么

| 图中的内容 | 平台通用表达 | EMS 专业化 |
| --- | --- | --- |
| Site 场站 | Site：一个现场的业务范围 | 增加能源总目标、相关并网条件 |
| Plant 电站 | Area：区域、系统或产线等组织容器 | Plant：具有电站模型与约束的 Area |
| ResourceGroup 资源集群 | Group：按明确用途引用成员的横向集合 | ResourceGroup：能源分配成员与共享限值 |
| EnergyUnit 柜体／能源单元 | Unit：对外提供业务能力的功能对象 | EnergyUnit：满足能源能力与约束的 Unit |
| PCS／BMS／电表等 Device | Device：独立接入设备实例 | 由能源 Profile 和成员角色表达其用途 |
| 测点／命令点 Point | Point：数据来源或只读派生值，带类型、单位与质量 | 功率、SOC、电量及具体物理设定／反馈 |
| Capability 能力 | 对外支持项、参数、当前可用性与约束 | 充放电功率、可用能量、限发／充电限制 |
| Adapter／Driver | Profile 声明厂商映射，协议适配执行通信 | 能源设备专用映射与已支持算法 |
| Scheduler／Controller | 已支持逻辑根据目标、能力和约束产生受控动作 | EMS 提供能源目标分配和专业安全规则 |

**Plant、EnergyUnit、ResourceGroup 是业务类型的专业化，不规定代码必须使用继承实现。** 普通设备不要求填写 SOC、kWh、PCC，也不要求先建立电站。

图中出现的 OpenHAB 兼容、完整协议清单、数据库、预测和跨站远程调度不因本次建模而进入范围。图里的自动命令重试不采用；超时结果与真实反馈继续按既有安全规则处理。

## 2. 通用对象及最小职责

### Site：现场范围

承载现场身份、名称和业务对象范围。同一项目可包含多个 Site，但多 Site 建模不等于已支持跨站远程协同控制。

### Area：组织容器

描述站内区域、系统、车间、产线或房间等组织层级；显示名称与业务类型由项目定义。Area 本身没有默认功率、调度或启停能力，EMS 的 Plant 类型才增加相应能源语义。

### Unit：功能对象

把一台或多台 Device 的观测、动作与过程组合为稳定的业务对象。例如供水单元对外提供压力、状态与启停；EnergyUnit 则提供能源能力。成员角色与对外操作须显式定义，不从成员清单猜出“整体启动”。

### Device：设备实例

代表现场或模拟环境中的独立设备身份，引用型号模型、模板和 Profile，保存实际连接与实例参数。它不是通信通道本身，也不必与一个总线站号一一等同。

### Point：数据项

描述明确来源或只读计算的数据，包含稳定身份、用途、类型、单位、来源时间、质量、读写方向及转换。属性使用 Point 的数据含义，但“业务属性”与“物理寄存器地址”不是同一层。

### Group：有用途的成员集合

按显示、统计或声明的业务用途组织成员，可引用不同 Area 的对象，不强制成为树中的父节点。成员类型、范围和聚合方式明确；Group 不因包含设备就获得广播命令或分配算法。跨 Site 控制不在本轮范围，EMS ResourceGroup 明确不跨 Site。

### 关系、能力、命令与事件

- **Relationship**：声明对象之间的关系角色，例如组织归属、单元成员、测量来源、控制作用对象或展示引用。关系名称不是权限凭证。
- **Capability**：描述对象支持什么观测或操作、参数范围、依赖条件、当前是否可用以及原因。额定、实时允许与本次可分配口径仅用于适用的量化能力，不给所有设备虚构数值能力。
- **Command**：业务动作及参数、允许条件和反馈要求。命令可映射到一个或多个已有设备动作，但不能退化成普通用户任意写寄存器。
- **Event／AlarmEvent**：状态变化与需要处理的异常过程。报警确认、异常仍在及设备恢复分别表达，不把事件名称当实际物理状态。

## 3. 层级是组织方式，关系才说明如何协作

默认可按“现场、区域、业务单元、设备、点位”组织，但不是必填五层：

- 一个 Site 可以直接包含普通 Device；独立传感器不必包装成 Unit。
- Area 与 Unit 仅在表达实际组织或功能时使用。Area 是容器，Unit 是有对外业务能力的对象，不能混为同义词。
- Group 是横向成员关系，不要求把成员从原来的组织位置搬走。EMS 的资源组因此可以跨 Plant，而不制造多个设备副本。
- 物理通信关系、业务归属、展示分组、测量来源和控制作用关系分别表达；改展示标签或位置不会隐式改变授权、控制范围或累计口径。
- 同一设备多处展示仍是同一个实例；共享测量不重复累计。同一最终受控目标不得通过不同 Unit、Group 或直接设备入口获得独立竞争写权。
- 成员与派生数据引用需有效，禁止循环。首版不因通用化承诺任意嵌套 Unit、任意关系图执行或自动组装逻辑。

## 4. 一套物模型，类型与实例分开

### 共同模型内容

| 内容 | 描述什么 | 使用原则 |
| --- | --- | --- |
| 身份与类型 | 稳定 ID、显示名、业务类型、模板引用 | 名称或位置变化不改变业务身份 |
| 属性 | 类型、单位、枚举、用途、默认值、允许范围、来源与历史方式 | 区分观测、配置、目标与反馈，不根据名称猜用途 |
| 命令 | 动作、参数、控制目标、条件和反馈 | 型号支持不等于当前用户和现场已允许执行 |
| 事件 | 业务含义、来源与关联对象 | 普通状态事件不强制走报警确认 |
| 能力 | 对外支持项及限制、有效性与原因 | 行业包决定专业量纲与算法，平台不默认相加 |
| 成员角色 | 组合对象所需执行、保护和测量成员 | 区分必需和可选，缺项只限制依赖它的功能 |

各类对象只声明自身需要的内容：组织容器不因为共有模型格式就必须具备命令；只读测量不因为具有属性就必须能控制。

### 模型、模板、Profile、实例的分工

- **模型**规定“是什么、对外有哪些属性和动作、各自含义是什么”。
- **模板**把模型和已支持的默认配置组合为可复用定义；Unit 模板还声明成员角色。
- **Profile**说明某厂商如何以物理点位、编码、单位和命令实现设备语义。
- **实例**填写这个现场的具体身份、连接、绑定与显式覆盖项。

模板与实例的参数差异必须可见；模板草稿不能静默改掉生效实例。这里仍是普通配置与明确应用，不恢复模板升级或合并流程。

## 5. 数据绑定与动作绑定

### 数据路径

协议采集的值经 Profile 解码、单位与枚举映射后成为有质量和时间来源的 Point 数据，绑定到 Device 或 Unit 的业务属性。规则、组态、报警和历史使用相同的语义与对象身份。

只读派生属性可以使用已支持的聚合，须保留输入、单位与质量。关键反馈失效不能用额定值、旧值或零填补成有效观测。

### 操作路径

用户或已配置逻辑对明确对象发起业务命令。平台依据当前能力、权限及安全条件处理，经已支持规则／状态机或行业算法映射到实际设备动作，再由 Profile 和协议适配执行。反馈更新实际属性、状态和能力。

原图的站级／电站级 Scheduler 是 EMS 算法职责，不是每个 Site 或 Area 都必须存在的通用调度器。上层目标不能默认平均分给下层：压力不能像功率一样直接相加，开关动作也不适用功率分配。

通用层统一“对象、能力、动作和结果”的含义，行业包提供专业协调策略；不要求用户操作内部仲裁与提交阶段。模型不会因为复用而获得新的权限或绕过互锁。

## 6. 三类应用用同一骨架

| 应用 | 组织与组合 | 对外业务含义 |
| --- | --- | --- |
| 简单监测 | Site 下直接放温度／压力 Device | 观测属性与报警，无需 Area、Unit 或能源字段 |
| 泵房 | Site、泵房 Area、供水 Unit，成员为驱动与传感器 | 压力、液位、运行状态、允许的启停；不增加首版未要求的自动轮换或恒压优化 |
| 光储充 | Site、电站类型 Area（Plant）、能源类型 Unit（EnergyUnit），ResourceGroup 关联分配成员 | 功率、能量、SOC、资源限值、计划、需量、防逆流和联合调度 |

EMS 保留最小可独立受控能源单元、有功组归属、逐 PCC 约束、充放方向及能源能力口径。其他行业复用通用对象，不被迫继承这些能源规则。

## 7. 换品牌属于建模与绑定

能力语义等价、Profile 已适配时，实际设备更换主要改变 Device 与厂商映射，Unit 对外模型及引用可以保持稳定。实际换机使用新 Device 身份，旧历史仍属于旧设备；修正同一设备的 Profile 不自动变成换机。

新设备可以先采集，控制启用仍需核对必要条件，不接收旧设备未完成命令。无 Unit 时，已确认的直接设备改绑方案仍在 US-40 场景走读中归纳；本次通用建模不强制引入 Unit，也不提前改写其尚待最终确认的故事与验收。

不等价的范围、模式、反馈或物理行为应明确提示，不承诺任意品牌无缝替换，不新增换品牌管理中心。

## 8. 验收与边界

**T40：通用物模型跨行业表达。** 使用同一套对象与模型机制建立简单监测、供水 Unit 和 EMS 模型：

1. 普通 Device 可直接使用，泵房无需能源字段；Plant／EnergyUnit／ResourceGroup 的专业规则只在相应业务类型生效。
2. 区域归属与 Group 成员关系不冲突；多处展示不复制资产或累计数据，展示分组不能隐式控制成员。
3. 模板／实例／Profile 分工清楚，业务引用稳定，设备地址变化不要求修改规则和画面代码。
4. Unit 成员与数据、动作绑定可解释，未知或缺失输入不伪造能力；权限和保护在所有入口一致。
5. 证明的是所声明样板的建模能力，不以该结果宣称支持任意行业、所有协议或标准认证。
