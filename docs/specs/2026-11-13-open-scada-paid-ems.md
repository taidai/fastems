## Problem Statement

交付人员需要把现场设备、点位和业务逻辑快速组成可运行应用。用户应围绕“接什么设备、数据是什么意思、满足什么条件做什么、画面怎样展示和操作”工作，而不是先学习检查、升级、仲裁和提交等内部流程。

平台的深度来自设备模型与实例复用、点表批量处理、可配置规则与状态机、AI 交互组态，以及 EMS 提供的能源模型和策略内容。后台的安全执行应可靠，但不成为主产品叙事。

## Solution

**让交付团队在已支持的设备与能力范围内，无需编写项目代码，即可构建、仿真、运行和交付可复用的 SCADA 应用，并通过付费 EMS 功能包配置能源管理与协同控制应用。**

### 最终用户拿到什么

- **交付人员**拿到能制作应用的工具：从空白或模板接设备、整理点位、建模配逻辑、让 AI 生成画面，然后把能运行的应用交给客户。未配置时明确下一步，不靠读源码或开发者代办。
- **现场操作员**拿到已配置的应用：登录后看到自己负责的现场，找得到设备、看得懂数据、做得了获准操作，异常时知道原因与下一步；无需理解 Profile、仲裁或发布机制。
- **客户管理员**能管理账号和对象权限；仅被显式授予工程权限的人进入工程配置。三个角色不是三套重复产品。

**取舍准则：** 不能帮助上述用户完成任务、减少重复配置或防止误操作的能力，不因“平台通常都有”而加入。能放在原操作中的提示与校验，不新建中心或流程。安全、真实反馈和明确生效状态不能为了少按钮而删除。

### 交付人员的制作主线

1. **接设备、管点位**：连接与 Profile，点表导入／批量编辑，查看原始值、业务值与质量。
2. **建模型、配逻辑**：设备模板与实例、业务拓扑、属性／命令／事件、只读派生数据、决策表和状态机。
3. **生成画面、直接使用**：AI 对话和标注截图生成／修改 2D、Three.js 页面；查看实时数据、报警和历史，并控制获准设备。
4. **配置能源应用**：EMS 的模型、策略模板、能流与运行画面直接用于上述项目制作流程，不另设“加入 EMS”工作台或安装向导。

最小工程交付保留：编辑、保存、预览、明确应用，以及项目导入导出和离线运行。没有独立交付检查中心、升级冲突流程、回滚／灾难恢复中心。必要输入校验和生成画面安全预览留在操作发生处，不伪装成重新引入的检查模块。

### 不能删的使用能力

| 用户任务 | 必须保留的能力 | 少了会怎样 |
| --- | --- | --- |
| 把设备接进来 | 连接、设备与 Profile 绑定，问题定位到实际对象 | 页面有设备名字，却不知道有没有读到设备 |
| 把数据整理正确 | 点表批量处理、原始／业务值对照、单位、质量与引用关系 | 逐点重复录入，错误缩放或坏值被当成真数据 |
| 同类设备不重复制作 | 模板、实例、拓扑、模型属性／命令／事件及只读派生数据 | 换设备就重做逻辑和画面，各页面含义不一致 |
| 表达条件联动 | 决策表的条件、顺序、持续／冷却、动作与模拟 | 简单现场逻辑也必须找开发者写代码 |
| 表达设备过程 | 状态、事件、守卫、转移与等待结果 | 点了启动就显示运行，过程和真实反馈混淆 |
| 看现场并操作 | AI 生成与修改组态，实时数据、报警入口和授权控制 | 只得到漂亮截图，不能完成现场工作 |
| 发现并理解异常 | 报警定位与处理、历史趋势、缺样显示和授权导出 | 知道异常却找不到原因，数据无法带走使用 |
| 配置能源应用 | 能源模型、PCC 关系、计划和策略模板、能流及参数操作 | EMS 只剩菜单和日志，仍靠手写项目逻辑 |

### 不能少的使用细节

| 使用时刻 | 用户必须获得的结果 | 复用验收 |
| --- | --- | --- |
| 登录／进入应用 | 按权限进入已配置运行页或工程入口；无项目／无连接时说明缺什么和下一步，不用空白页冒充正常 | T01、T26 |
| 找设备／切换现场 | 看得见当前项目、站点和设备；从列表、画面或报警定位同一对象，切换后不沿用旧目标操作 | T16、T31 |
| 读一个数值 | 看得见名称、单位、必要的时间／质量；无数据、正在加载、读取失败和过期分别说明，不能一律显示零或绿色正常 | T27、T28、T32 |
| 配置／导入后 | 知道哪些成功、哪些失败、当前是未保存／已保存未生效／已生效；失败保留可修正内容，离开未保存编辑有提醒 | T13、T26、T33 |
| 点控制按钮前后 | 明确目标、动作和参数；不能操作时说明原因，发出后有真实反馈，等待或结果未知不伪装成功 | T04、T17、T31 |
| AI 不可用 | 模型网络、凭据、额度或生成失败有可理解提示；保留现有画面与修改上下文，不影响已部署应用的使用 | T05、T08 |
| 报警发生 | 从报警能回到相关设备、当前数据和历史；确认接手不等于设备故障解除 | T01、T32 |
| 换同事／交给客户 | 常用任务可从界面及项目使用说明完成，不要求理解内部术语或通过后台改数据 | T26 |

这些是原页面与操作的必要反馈，不是新增检查、升级或运维模块。3D 是展示方式，不能让完成一个常用操作必须先学会旋转和寻找模型；同一画面应有清楚的设备选择与操作入口，不另建手工组态编辑器。

### 配置一次，多处复用

- **同类设备共用画面定义**：AI 生成的画面或片段声明所需模型和实例参数；绑定另一台设备时，名称、数据、报警和操作目标一起切换，不重新生成整页。不匹配、缺参数或单目标不唯一时明确提示，不能猜测操作对象。
- **通用规则模板填参复用**：决策表模板声明类型化输入、动作目标和可调参数；使用时只绑定实例及差异参数。各实例互不影响，保存仍不等于生效，不复制模板示例设备作为隐藏目标。

复用依据明确的模型用途和关系，不依赖显示名称；型号支持能力与当前是否允许操作分开。其余局部质量和报警过程要求在现有能力与验收中补齐，不新增模块、手工组态编辑器、脚本语言或复杂流程。

### 通用 Unit 与 EMS 专业化

平台提供可选 Unit（业务单元），用模板将多个 Device 的属性、命令和事件组合成稳定业务对象。例如供水单元绑定驱动和传感器，对外提供压力、运行与启停；普通传感器仍可直接使用，无需套 Unit。

EnergyUnit 是符合 EMS 能源契约的 Unit。通用层负责身份、模板、成员角色、对外模型及能力可用性描述；EMS 包负责 SOC、kW／kWh、PCC、充放电约束和能源分配。不能只改 energyUnit 名称，或把能源字段强加给所有 Unit。

EMS 需要补全三项业务结果：**层级目标与约束共同生效；额定、实时允许和本次可分配能力分别解释；多设备明确角色、聚合和动作反馈。** 用户看目标、可满足部分与受限原因，不增加内部控制流程菜单。具体规则与 T36–T39 见 Unit 模型细则。

### 首版样板

- 泵房 SCADA：两台泵、一个水箱，Modbus RTU 行为模拟，监控与受控启停，不要求能源对象。
- 并网储能：PCC 电表、两组独立受控储能单元，配置计划、需量、防逆流和能力约束。
- 并网光储充：增加光伏和充电资源，配置同一 PCC 下的联合目标及画面。

每个样板独立证明接入、建模、逻辑、画面、操作及离线运行；能源样板分别验证换厂商 Profile。既有模块测试可复用，但不能拼接不同项目的局部成功，冒充完整应用。升级回滚和交付检查不再是样板必验项。

#### 如何登记证据

每条实际证据至少说明：对应目标与测试编号、工程／代码版本、设备或模拟器及配置、执行时间和人员／自动化工具、实际步骤与结果、记录位置和未覆盖范围。敏感信息不得随证据公开。

只完成局部时记录“局部已验证”并列明缺口；失败和未执行分别记录，不能因为脚本退出成功而更新为目标完成。模型固定响应、虚拟串口、物理链路、真机与独立用户试用互不替代。同一目标在储能与光储充上适用时，分别登记，不能拼成一份不存在的完整项目结果。

## Implementation Decisions

用户界面围绕任务组织，不把内部机制逐个做成菜单。点位、模型和操作身份一致；保存与生效清楚；权限、互锁和真实反馈由平台承担，不让用户替软件处理仲裁与提交阶段。

对象分工、内部可靠性、运行形态与商业约束移至[附录 D](#appendix-d)，供设计和实现时查阅，不要求终端用户学习。具体字段和配置行为见平台能力细则。

## Testing Decisions

主测试入口仍是实际应用与正式设备通信路径，但产品本身不新增检查工作台。每个样板从空白完成配置并运行；点位、模型、规则、状态机、AI 操作和报警历史都有正向与失败场景。

虚拟 RTU 经过真实帧、CRC、站号和串口读写，不能用 TCP 或内存赋值替代；物理串口与目标设备仍独立签收。AI 固定响应测试与真实生成效果分开，付费调用另需预算授权。离线运行验证冷缓存下脚本、模型和素材本地可用。

用户验收关注“能配、能用、含义一致”；仲裁、命令阶段和故障安全由底层回归守住，不要求用户逐阶段走运维流程。量程、时序、容差和性能目标在相关测试前明确，不凭空承诺覆盖率或无限容量。

当前测试见附录 B。退出范围的检查／升级／恢复测试列入附录 C，仅作历史索引，不计本轮缺口或完成门槛。

## Out of Scope

- 独立交付检查中心、问题清单工作流、评分／验收状态机。
- 升级差异与三方合并、版本回滚、备份／灾难恢复中心、授权迁移恢复流程。
- “加入 EMS 能力”独立用户旅程、包安装向导、能力市场；EMS 功能内容本身保留。
- 用户必须理解或操作的仲裁、提交、命令阶段管理中心；必要后端保护与诊断不删除。
- 首版离网、STS 切换、黑启动；泵房自动轮换、恒压优化；任意后端控制脚本。
- AI 自主实时控制、网页直写设备、多模型市场、强制云订阅和热插拔框架。
- 没有证据的厂商／协议支持、性能保证；以模拟器冒充真机；直接同步 GitHub、提交或修改产品代码。

## Further Notes

本轮从“交付运维流程”转向“平台开发能力”。旧规格和白话说明中的检查、升级恢复及加入 EMS 章节不再构成当前需求；历史文字以最新范围说明为准。减少运维叙述不改变权限、互锁、命令真实性及数据保护要求。

## Appendix D

### 设计与实现参考（不转化为用户流程）

### 1. 点位、模型、实例与 Profile 分工

连接负责取得数据；点位负责描述数据来源、类型、转换、单位、时效和读写方向；物模型负责稳定业务属性、命令和事件；Profile 将厂商物理点位映射到逻辑含义。设备实例复用模型定义，保留自己的身份、现场地址及覆盖参数。

平台通用 Unit 在这些对象之上提供独立业务身份、成员角色和对外模型，复用现有规则／状态机表达组合行为；不复制一套点位或设备通信体系。模板、模型和画面可面向 Device 或 Unit，绑定时验证契约。EnergyUnit 是 EMS 的专业化 Unit，能源数值、PCC 和分配规则不进入通用对象的必填字段；具体持久化和代码实现另行设计。

规则、状态机、画面和历史引用稳定对象，不靠中文名称猜测含义。点表批量操作必须定位错误和引用影响；派生聚合说明输入和质量，不用缺省零掩盖缺值。字段与交互细节见能力细则。

模型成员声明观测、配置、目标或反馈等用途及历史记录方式；配置留痕不冒充传感器实测。展示归属与反馈／控制关系分开，纯展示位置或标签变化不隐式修改授权、PCC 或累计口径，展示组不自动广播命令。

型号定义说明支持哪些操作及参数约束，平台另给当前身份和现场条件下是否允许及原因；局部数据失效按成员分别表达，不用全局在线图标代替动作所需输入判断。

### 2. 可配置逻辑与 EMS 功能内容

通用决策表和状态机属于开源底座。能源模型与专业策略属于 EMS 包，复用相同接入、逻辑描述、画面、权限和历史能力。EMS 包应提供可直接配置的内容，不只是菜单开关，也不要求另走“加入能力”流程。

首版能源内容包含储能、光伏、充电及适用可削减资源的模型和能力；PCC、资源关系、96 点计划、15 分钟滑动需量、防逆流、资源限值和联合调度模板。模板明确所需输入、可调参数、作用资源及支持条件，缺失能力直接指出，不猜测、不静默补值。

能源页面优先显示设备能力、目标与实际值、计划和能流，以及为什么受限。仲裁、提交阶段与关联日志留作按需诊断和底层测试，不是独立产品模块。

### 3. AI 组态支持实际操作

首接 DeepSeek，用户自备凭据；AI 生成网页代码，3D 用 Three.js，全部通过对话或标注截图修改。控件绑定模型中实际存在且获准的启停、模式、设定值和运行参数操作。用户选择设备、核对操作并确认后，由平台执行，页面展示反馈或明确失败／未知。正式运行不依赖模型在线。

生成代码在预览与运行时均受隔离；预览默认连接模拟设备。网页不持有设备凭据，不直写协议，不绕过平台权限和互锁。模型输入限于获准工程内容和截图，不默认发送秘密、现场地址或运行数据。失败生成保留上一可用画面和修改上下文，而不是依赖人工修代码。

### 4. 最小项目与运行形态

保留一个 Go 业务服务、离线 Docker 运行、一个现场实例运行一个项目。项目可组织多个 Site；多个独立工程不混在一个运行实例中。

项目保存模型、点表、Profile 引用、规则、状态机、画面源码与确定产物、固定依赖和仿真场景。保留导入导出与干净实例运行同一工程；新现场重新绑定地址、凭据和授权。项目包不含升级迁移工作流或灾难恢复承诺。

编辑／草稿与当前生效内容分开，明确应用前不改变现场逻辑；已开放参数可在授权范围内调整。此处是必要编辑行为，不建设独立变更管理中心。生成网页及资源随工程离线提供，不依赖 CDN。

### 5. 底层可靠性要求（不作为用户流程）

- 服务端校验身份、对象、参数和互锁；重复点击不无意重复动作；界面反馈不得把命令已发出冒充设备已执行。
- EMS 保持唯一最终写入所有权、安全约束优先、充放方向能力限制和逐 PCC 校验；过期或坏值不授权新控制。这里淡化展示，不删除控制保护。
- 人工接管、故障、断线重连和进程重启不得重放旧命令；故障处理按场景确定，不统一置零或擅自恢复输出。
- 96 点计划空段不补零。需量遵循既有 15 分钟滑动窗口及一分钟分段规则；缺样说明不可用，独立安全限制仍有效。
- 报警、历史、操作与控制记录真实保留；无效输入、未知结果和数据缺口明确表达。生成画面预览和字段校验不等于独立“检查”模块。

### 6. 权限与商业约束

操作员看数据、处理报警并执行获准操作；工程编辑要求相应权限。客户可获授工程权限，不以身份永久禁止。运行历史查询和导出不以购买 EMS 为前提。

EMS 继续按生产运行实例授权，开发模拟不占生产授权；到期不打断既有授权现场运行或关闭基本安全能力。具体付费增量须与既有 Apache-2.0 权利区分。授权迁移、故障换机恢复及复杂包管理不属于本轮功能交付，既有商业承诺留作历史记录，不由本轮撤销或默认实现。
