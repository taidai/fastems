# 模块功能与页面逻辑审查

日期：2026-11-06
范围：v1 现有页面与数据模型；目标是回答“每个模块还能补什么”和“页面结构是否自洽”，不扩大冻结范围。

## 1. 当前页面与对象

| 页面 | 主要对象 | 当前职责 |
| --- | --- | --- |
| 站点总览 / 工作台 | 站点、KPI、能流 | 总览、健康摘要、事件条 |
| 运行画面 | 业务节点、点位 | 受控运行画面 |
| 点位表 | 点位 | 实时值、质量、批量管理、写值回读 |
| 通道 | 端口、单元、点位 | 健康、端口参数、单元与点位、点表模板 |
| 虚拟聚合 | 业务节点、点位 | 只读求和/平均/最值/计数 |

| 功率分配器 | 业务节点、PCS 成员 | 目标分配、能力、回读 |
| 报警与事件 | 报警键、类型 | 记录、类型、统计与提醒、维护 |

## 2. 每个模块还能补什么

### 2.1 站点总览

- 可配置 KPI：选择要展示的指标、顺序和阈值，而不是固定 8 项。
- 健康摘要下钻：点击“离线/过期/告警”直接进入对应设备或点位。
- 班次交接：值班人留言、未处理事项、下一班关注点。
- 快速动作：常用命令、确认报警、打开当前站点画面。
- 能耗基线：今日/昨日/上周同期对比；仍只展示已接入点位。

### 2.2 运行画面

- 画面模板：按角色（值班、运维、站长）复用。
- 仪表/趋势嵌入：画面上直接显示趋势和报警摘要。
- 受控操作确认：画面上的写值/命令必须有权限、确认和回读结果。
- 画面版本与回滚：保存草稿、发布、历史版本。
- 不引入自由拖拽编辑器；保持受控布局。

### 2.3 点位表

- 点位角色分类：遥测/遥信/电度/定值/压板，或“测量/状态/电能/设定/保护”。
- 质量原因：区分无值、过期、通道离线、设备故障、命令未知。
- 行内趋势：不跳页看最近 1 小时。
- 保存筛选/视图：按通道、质量、角色、读写保存为常用视图。
- 点表导入 diff：预览新增/修改/删除，而不是只显示数量。
- 写值确认：批量写前确认目标与范围；失败项可重试。

### 2.4 通道

- 单通道重启/重连：不重启整个应用。
- 串口线路测试：不保存配置也能测收发。
- 端口配置 diff/模板：复制端口、对比变更。
- 扫描/识别内联：在端口页直接扫描站号并带入点表。
- 单元健康汇总：按站号显示成功率、延迟、最近错误（已有质量统计基础）。
- 报文查看已完成；可增加按设备过滤和保存最近一次故障报文。

### 2.5 设备模型与命名命令

- 设备台账：一台设备一行，显示业务节点、通道/站号、Profile、点位数、命令数、验证状态。
- 设备详情：概览/点位/命令/历史/告警/验证一个抽屉完成。
- 命令历史：谁在何时执行了什么参数、结果、request_id；当前只有实时结果。
- 参数预设：常用参数值保存为预设，减少现场输入。
- 批量命令：对同 Profile 的多台设备执行同一命令，逐台回读。
- 试运行/影响预览：显示将写哪些点、当前值、安全限制，不真正下发。
- Profile 验证清单：地址/缩放/字序/写授权逐项勾选并留证据；已有导出基础。

### 2.6 虚拟聚合

- 时间窗口聚合：最近 5 分钟/1 小时平均、最大。
- 质量策略：全部有效/部分有效/任一有效，当前已有部分有效标记。
- 虚拟设备告警：对聚合值配置阈值。
- 报表绑定：聚合值作为报表列；仍保持只读。

### 2.7 决策表

- 策略模板：防逆流、需量控制、峰谷套利、光储跟补（v1.1）。
- 时间窗口/星期/跨午夜条件（v1.1）。
- 场景测试集：保存一组输入，回归规则命中。
- 版本 diff：两个发布版本的条件/动作差异。
- 历史快照回放：用某时刻点位值模拟，不写设备。
- 规则依赖图：显示规则、点位、分配器的引用关系。
- 条件分组/OR（v1.1；当前行内 AND 保持不变）。

### 2.8 功率分配器

- SOC/温度/电网限值作为成员约束，而不只靠外部条件。
- 优先级/权重分配，而不只按可用功率比例。
- 分配历史与导出：每次目标、实际、回读、剔除原因。
- 死区/最小调整量：避免频繁小幅重分。
- 手动接管与恢复：成员级接管，恢复后重新参与。
- 模拟分配：不写设备，只看结果。

### 2.9 报警与事件

- 报警分组/根因：同一通道或同一设备的连锁报警合并。
- 报警洪泛抑制：短时间重复报警合并计数。
- 确认备注：确认人填写处理说明；当前只记录确认人。
- 报警历史导出：当前有统计和 CSV 吗？统计有，历史导出可补。
- 报警到规则/点位下钻：从报警直接打开来源点位和最近报文。
- 本地通知：声音/静默已完成；邮件/短信保持不做。

### 2.10 数据与追溯 / 设备数据查询

- 报表模板：历史报表、用能报表、Excel 模板导出（v1.1）。
- 聚合间隔：原始/1 分钟/1 小时，避免大时间范围一次拉 2000 点。
- 保存查询：按设备、点位组、时间范围保存视图。
- 多设备对比：同一时间轴对比多个点位。
- 报警叠加：趋势图上标注报警发生/恢复。
- 数据质量摘要：缺失段、过期段占比。
- 设备查询与设备详情合并，避免“查询/追溯”两个入口。

### 2.11 部署与验收 / 交付检查

- 引导式接入向导：扫描 → Profile → 点表 → 试读 → 验收。
- 点表 diff 与回滚。
- 通信测试报告：端口、站号、地址、读取值、延迟。
- 备份验证：在线备份未验证前保持 warning。
- 交付证据包：验收项、截图、操作人、时间、设备序列号一键导出。
- 部署与交付可合并为“接入与验收”一个工作区，用页签区分。

### 2.12 账号、审计

- 权限到动作：查看/写值/命令/配置/发布分开授权，而不只角色。
- 会话策略：超时、强制退出、密码重置。
- 审计对象详情：当前是路径，后续可记录对象名称和变更摘要。
- 审计导出与保留策略；不要记录密码/令牌/请求体。

## 3. 页面逻辑是否自洽

结论：**功能基本齐全，但对象模型和导航不完全自洽。** 主要问题：

1. **“设备”被拆成三种东西**
   - 业务树里的 group 是业务设备；
   - 通道里的“单元”（通道+站号）是物理设备；
   - 点位表里的点位是数据点。
   - 命令/Profile/验证绑定在单元上，业务节点只是可选字段；规则又绑点位/分组。用户无法在一个地方回答“这台 PCS 是什么、属于谁、用什么 Profile、有哪些命令、验证了吗”。

2. **导航分类与心智模型不一致**
   - “运行画面”在“设备”下，但它是监控入口，应该在“总览”。
   - “功率分配器”在“设备”下，但它是调度控制，应该在“调度”。
   - “报警与事件”在“报表”下，但它不是报表，应该靠近运行/数据。
   - “设备数据查询”和“数据与追溯”职责重叠。
   - “部署与验收”和“交付检查”职责重叠。

3. **同一配置有多个入口**
   - Profile/CSV 出现在部署页和通道“点表与模板”。
   - 点位 CSV 导入/导出出现在点位表、通道工具和部署页。
   - 命令在设备模型里，普通写值在点位表/规则里，操作员需要判断走哪条路。
   - 报警声音在报警页、电价在显示设置、历史保留在历史页，运行设置分散。

4. **命名不统一**
   - 页面标题“设备与点位”、目录“点位表”、底栏“设备”。
   - “站点总览”与“工作台”混用。
   - “通道”曾是“通道与设备”，现在设备语义仍混在通道里。

## 4. 建议的目标信息架构

底栏五项保持不变，但重新归类：

- **总览**：工作台、运行画面
- **设备**：设备台账（新增/整合）、通道、点位表、虚拟聚合
- **调度**：决策表、功率分配器
- **数据**：报警与事件、历史与报表、设备数据查询（或并入设备台账）
- **配置**：接入与验收（部署+交付）、账号与权限、审计日志、运行设置

### 设备台账（最关键的一步）

先做 UI 整合，不急着改数据模型：

- 一行一台设备：业务名称、业务节点、通道/站号、Profile、点位数、命令数、健康、验证状态。
- 点击打开设备详情抽屉/页面：概览、点位、命令、历史、告警、验证。
- 从设备详情可跳到通道端口、点位表、历史、报警，但不再重复配置。
- 通道页只保留传输与端口；点位表只保留点位；设备台账负责“这台设备是什么”。
- 现有单元模型可以先作为设备台账的数据来源，不必立刻新增节点类型。

### 后续数据模型（v1.1）

如果需要严格稳定业务身份，再把 group 升级为第一类设备实例，保存 Profile、通道/站号引用、点位映射、命令、验证记录；规则/报警/聚合绑定设备实例，而不是可变的通道地址。这个迁移成本高，应单独设计，不在 v1 内偷偷做。

## 5. 建议优先级

**P0（结构自洽，不加新功能）**
1. 设备台账 + 设备详情，统一命令/点位/历史/告警/验证入口。
2. 导航重排：运行画面→总览，分配器→调度，报警→数据，部署+交付合并。
3. 去重：Profile/CSV 只保留一个主入口；点位 CSV 只保留点位表入口或通道工具入口。
4. 统一命名与页面标题。

**P1（使用效率）**
- 点位角色分类、质量原因、保存筛选视图。
- 命令历史、参数预设、批量命令、影响预览。
- 报警分组/根因、确认备注、报警下钻。
- 报表模板、聚合间隔、多设备对比。

**P2 / v1.1**
- 时间窗口/策略模板、分配器优先级/SOC/温度约束、自由拖拽画面（仍不建议）、通知组/云能力（不做）。

## 6. 约束

- 不引入第二套设备模型或第二套存储来“看起来整合”。
- 不为了导航好看而隐藏权限边界。
- 不把设备台账做成只读展示：它必须能进入配置、命令、历史和验证。
- 真实设备验证仍以 M5 现场为准；页面整合不能替代签收。
