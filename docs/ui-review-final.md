# 界面评审：以终为始

日期：2026-11-06
修复状态：见 [`ui-review-status.md`](ui-review-status.md)。P0 已完成，P1 完成关键项，P2/v1.1 仍未开始。
评审基准：现场值班员、实施人员、管理员能否在 10.1 寸触摸屏上少看错、少点错、能追责。视觉不是唯一标准，最终标准是“看懂 → 判断 → 操作 → 追溯”闭环。

## 1. 总评

| 维度 | 分数（1–5） | 判断 |
| --- | --- | --- |
| 视觉完成度 | 4 | 玻璃主题统一、能流与卡片有辨识度 |
| 信息架构 | 2.5 | 设备对象被拆散，入口重复，导航刚归位但仍有交叉 |
| 任务闭环 | 3 | 报警、命令、审计有闭环；部署/验收、查询/历史仍未收口 |
| 10.1 可用性 | 2.5 | 页面不滚动，但字号、列数、汇总卡片在 1024 下明显吃力 |
| 一致性 | 3 | 组件风格统一，命名、默认选中、空状态不一致 |
| 可信/可解释 | 2.5 | 存在 501 假状态、审计动作显示“其他”、技术路径直达用户 |

**结论：这是一个视觉成熟的原型，还不是一个可以交给现场值班员长期使用的操作台。** 主要差距不在“再多几个功能”，而在对象边界、可信状态和 10.1 阅读/触摸。

## 2. 做得好的地方

- 玻璃主题、背景照片、底部导航和能流画面形成了统一的产品识别。
- 页面级、舞台级、横向滚动基本为 0；10.1 一屏目标守住了。
- 报警/命令/审计都有 request_id、状态、原因，方向正确。
- 点表、通道、报警、审计的表格密度高，适合熟练用户。
- 空状态文案总体清楚，不是只放一个空白页。
- 权限、维护、验证、参数等“现场语义”开始进入界面，而不是只存在于 API。

## 3. P0：必须先修的可信与结构问题

### 3.1 部署页显示“运行状态接口尚未接线（501）”

- 事实：部署页仍请求 `/ems/runtime`，该接口没有实现，页面直接显示“501 尚未接线”；但同一实例的通道、质量、点位、报警都正常。
- 影响：这是**自相矛盾的状态**。实施人员会怀疑整个系统；验收页也不可信。
- 根因：页面没有跟随后端接口演进，保留了旧的 M4 占位文案。
- 处理：要么接上真实运行状态（复用 channels/quality/points 统计），要么删掉该卡片，不要显示 501。

### 3.2 审计日志不是“业务审计”

- 当前大量记录显示动作“其他”、对象 `/tariff`、`/ems/alarms/.../ack`、`/modbus/.../units/1/model`。
- 现场人员看不懂 `/tariff` 是什么，也无法从对象路径判断改了哪个站点/设备。
- 影响：不满足“每个动作可解释、可追责”的产品目标。
- 处理：动作映射到业务动作（修改电价、确认报警、保存设备模型、命令执行）；对象记录业务名称 + 类型 + ID；路径只放详情。
- 同时：审计页默认应显示最近业务动作，而不是技术路径列表。

### 3.3 设备台账仍是“索引”，不是“设备详情”

- 台账只有 2 行、名称都是“站号 1”，显示“未绑定 Profile”；详情只提供四个月跳转按钮。
- 没有在设备详情内直接看到点位、命令、历史、告警、验证页签；用户点“详情”后又回到通道/点位/历史找同一台设备。
- 影响：设备对象没有真正收口，台账只是另一个入口。
- 处理：设备详情做成一个抽屉/页面：概览、点位、命令、历史、告警、验证；命令和验证复用现有接口。台账行显示业务名称，站号只做副标题。

### 3.4 10.1 阅读与触摸不达标

- 1024 实测：KPI 卡片约 120×75，标签实际约 10px；台账汇总卡片高度约 27px，标签明显被压扁/截断；点位表 10 列，地址/时间/操作挤在一起。
- 触摸目标：不少表格“详情”“配置端口”“报文”“保存”按钮高度低于 44px；10.1 触摸屏容易点错。
- 影响：值班员在 10.1 上看不清、点不准，再好的功能也用不起来。
- 处理：
  - ≤1280 时 KPI 改 4×2，不强行 8 列。
  - 台账汇总改 3×2 或 2×3，保证卡片最小高度 60px。
  - 点位表 ≤1150 隐藏“格式/缩放单位/更新时间”等次要列，详情抽屉展示；或提供“表格/卡片”切换。
  - 表格行高 ≥44px，主要按钮 ≥44px；文字不低于 12px（真实像素）。
  - 玻璃透明度在表格页略提高，保证背景亮时对比度。

### 3.5 关键动作缺少确认与后果提示

- 运行画面卡片的“下发”直接调用写值，没有确认；规则“发布”也是重大动作。
- 点位表/批量删除有确认，但单点写值、画面写值的风险提示不一致。
- 影响：触摸屏误触会直接改变设备目标值。
- 处理：所有写值、命令、发布、删除统一确认；确认框写清对象、当前值、目标值、后果和回读等待；高风险动作要求二次确认或更高级权限。

### 3.6 重复入口仍然存在

- “设备数据查询”与“数据与追溯”“设备台账”重叠；“部署与验收”与“交付检查”重叠。
- Profile/CSV 在部署页和通道“点表与模板”出现；点位 CSV 在点位表、通道工具、部署页出现。
- 影响：用户需要判断“这次该去哪个页面”，同一配置可能改两处。
- 处理：设备详情承担查询；历史只做点位趋势；Profile/点表工具只保留一个主入口；部署与交付合并为“接入与验收”页签。

## 4. 逐页评审

### 4.1 站点总览

- 优点：能流、KPI、事件条一屏完整，视觉是产品最强页。
- 问题：8 个 KPI 在 1024 下过密；大量 KPI 为“—”时没有“去接入点位”的行动；页头健康摘要字号过小，几乎不可读。
- 建议：KPI 可配置/排序/阈值；≤1280 改 4×2；“—”卡片点击直达对应点位/通道；健康摘要变成可点击的状态胶囊；增加班次交接与常用命令入口。

### 4.2 运行画面

- 优点：卡片式实时值、历史、下发入口清晰；报警条在顶部。
- 问题：没有画面模板/版本；卡片只显示“最近一小时暂无趋势”，没有真正嵌入趋势；直接下发无确认；没有画面级报警/控制权限说明。
- 建议：模板与版本回滚；嵌入迷你趋势/报警；受控操作确认和回读反馈；按角色选择默认画面。

### 4.3 设备台账

- 优点：方向正确，第一次把设备作为一行。
- 问题：空、浅、名称重复；汇总卡片在 1024 被压扁；没有详情页签；未绑定 Profile 没有“去绑定”的 CTA；没有命令/验证状态的可操作入口。
- 建议：设备详情六页签；行内“绑定 Profile/验证/命令”快捷动作；空状态直接引导到通道配置；合格设备行显示业务名称，站号作副标题。

### 4.4 点位表

- 优点：高密度、批量操作、实时值与质量齐全。
- 问题：标题“设备与点位”与目录“点位表”不一致；10 列在 1024 拥挤；没有点位角色分类；质量只显示“过期/无值”，没有原因；默认选中/排序没有业务含义；同一名称重复出现难以区分。
- 建议：角色分类、质量原因、保存视图、列显隐；≤1150 隐藏次要列；点行打开抽屉而不是只有一个“详情”；行内趋势。

### 4.5 通道

- 优点：三页签收口得好；健康、质量、报文、端口参数在同一工作区；卡片的成功率/延迟有效。
- 问题：单元健康只到端口卡片；设备模型/命令藏在单元行；没有单通道重启/线路测试；没有配置 diff/模板；通信质量统计没有错误分类。
- 建议：单通道重启/重连、线路测试、扫描内联、单元健康汇总、配置 diff/模板。

### 4.6 虚拟聚合

- 优点：左配置右结果，质量传播可见。
- 问题：右侧大面积空白；成员列表没有搜索/分组；没有时间窗口；没有虚拟告警；保存后缺少“当前结果来自哪些成员”的解释。
- 建议：时间窗口、质量策略、虚拟告警、报表绑定、结果解释。

### 4.7 决策表

- 优点：有序表、模拟、发布、版本历史方向正确；表格/详细视图降低编辑成本。
- 问题：默认打开一张空规则，整页大面积空白；没有策略模板/场景测试/版本 diff/依赖图；发布栏在 1024 偏小；规则与设备/分配器的关系不直观。
- 建议：模板、场景测试集、版本 diff、历史快照回放、依赖图；默认选择最近编辑或已发布规则，不默认空规则。

### 4.8 功率分配器

- 优点：空状态清楚，业务节点、宽限期、回读超时、成员入口完整。
- 问题：没有分配历史/模拟分配；没有优先级/权重/ SOC/温度/电网限值；0 成员时页面大面积空白；“保存分配器”禁用原因可见但不够显眼。
- 建议：成员约束、优先级、分配历史、死区、成员级接管、模拟。

### 4.9 报警与事件

- 优点：活动/未确认/恢复待关闭清楚；维护与结束维护、统计与提醒都在同一页；声音/静默可用。
- 问题：1 条报警时卡片下方大面积空白；没有分组/根因/洪泛抑制；确认没有备注；报警对象显示“#1”这类技术名；没有从报警下钻到点位/报文；历史导出缺失。
- 建议：分组/洪泛抑制、确认备注、业务对象名、点位/报文下钻、历史导出、报警到规则/设备详情。

### 4.10 数据与追溯 / 设备数据查询

- 优点：历史趋势、保留设置、设备树查询都在；查询页在 1024 仍可用。
- 问题：历史默认选到“风阀”这种无数据点位，整页空白；查询与台账/历史重复；没有聚合间隔/保存查询/多设备对比/报警叠加；数据质量摘要缺失。
- 建议：默认选最近有数据的点位；聚合间隔、保存查询、多设备对比、报警叠加、质量摘要；设备查询并入设备详情，历史保留为点位趋势。

### 4.11 部署与验收 / 交付检查

- 优点：扫描、Profile、点表、验收入口集中；只读探测边界清楚。
- 问题：501 假状态；没有引导式接入向导；点表没有 diff；没有通信测试报告/交付证据包；部署和交付职责重叠。
- 建议：向导、点表 diff、通信报告、证据包；部署与交付合并。

### 4.12 账号 / 审计

- 优点：账号范围、审计导出、维护记录都有。
- 问题：权限只到角色/树范围，没到动作；审计对象是路径、动作“其他”；没有会话策略/密码重置；审计没有对象业务名。
- 建议：动作级权限、会话策略、审计业务对象/动作映射、保留策略。

## 5. 目标页面结构（以终为始）

- **总览**：工作台、运行画面
- **设备**：设备台账（主入口）、通道、点位表、虚拟聚合
- **调度**：决策表、功率分配器
- **数据**：报警与事件、历史与报表、设备数据查询（逐步并入设备详情）
- **配置**：接入与验收（部署+交付）、账号与权限、审计日志、运行设置

### 设备详情必须是完整工作区

一台设备打开后：
- 概览：业务节点、Profile、健康、成功率/延迟、验证状态。
- 点位：该设备全部点位、质量、写值回读。
- 命令：命令列表、参数、执行历史、试运行。
- 历史：该设备点位趋势与报表。
- 告警：该设备活动/历史报警。
- 验证：验证人、日期、序列号、点表核对、导出。

这样“设备数据查询”不再需要独立存在；点位表聚焦批量管理，历史页聚焦跨设备对比。

## 6. 优先级

**P0（可信与可用，先于新功能）**
1. 修掉部署页 501 假状态。
2. 设备详情六页签；台账行显示业务名称，未绑定 Profile 给 CTA。
3. 审计动作/对象业务化。
4. 10.1：KPI 4×2、台账汇总重排、点位表列显隐、行高与按钮 ≥44px。
5. 写值/命令/发布/删除统一确认。
6. 合并重复入口（查询→设备详情，部署+交付，Profile/CSV 单一入口）。

**P1（运营效率）**
- 点位角色/质量原因/保存视图/导入 diff/行内趋势。
- 通道重启/线路测试/扫描内联/配置 diff。
- 命令历史/参数预设/批量命令/试运行/验证清单。
- 报警分组/洪泛/确认备注/下钻/导出。
- 总览可配置 KPI/健康下钻/班次交接/常用命令。

**P2（v1.1）**
- 时间窗口/策略模板/场景测试/版本 diff/历史回放/依赖图。
- 聚合时间窗口/虚拟告警/报表模板/多设备对比。
- 分配器 SOC/温度/电网约束、优先级、历史、模拟。
- 交付向导/证据包/动作级权限/会话策略。

## 7. 设计规范补充

- 10.1 真实像素：正文 ≥12px，表格 ≥12px，标签 ≥11px，关键数字 24–30px；主要按钮/行高 ≥44px。
- 玻璃透明度在数据表页提高，优先保证对比度；不要让背景照片吃掉表格线。
- 一个页面只保留一个主行动按钮（绿色）；其余为次级按钮；危险动作红色且需确认。
- 状态色语义固定：绿=正常/在线，琥珀=过期/未验证/维护，红=严重/离线/失败；未验证与过期不要共用同一视觉强度而不加文字。
- 默认选择必须“有内容”：规则默认最近编辑/已发布，历史默认最近有数据点位，设备查询默认最近有活动的设备。
- 所有“空”必须有下一步：去接入、去绑定、去验证、去配置。

## 8. 本轮结论

界面已经具备“好看、统一、信息密度高”的基础，但在最终用户视角下，最需要补的不是功能数量，而是：
1. **可信**：不要出现 501 假状态、技术路径审计、无确认写值。
2. **对象**：设备必须成为第一类工作区，而不是台账、通道、点位、查询四个入口的拼接。
3. **10.1**：字、列、按钮和汇总卡片必须按真实触摸屏重新排。
4. **收口**：删掉重复入口，把查询并入设备详情，把部署与交付合并。

这四点完成后，再按模块清单补功能，才不会越做越乱。
