# IoT 无代码开发交付平台：最终结果说明（历史讨论记录）

> 当前目标与验收以 [FastIOT 产品规格](specs/2026-11-13-open-scada-paid-ems.md) 为准（本地评审修订暂未同步 GitHub）。本文的 EMS 为中心、发布自动部署、统一禁止脚本及原架构备选口径不再约束新目标：底座可独立交付，允许受控 AI 前端代码，发布、部署和启动控制是不同动作。以下保留历史讨论，不据此新增实现范围。

## 核心目的

让反复交付 EMS 项目的团队，**不编写项目代码，也能把已验证的设备接入、物模型、策略和验收资产复用到新站点，只处理变化项与例外项，安全、可验证地交付光储充 EMS**；终端客户无需理解平台，即可使用完整的监控、报警、控制、追溯与日常运维功能。

这里的“无代码”指交付人员不编写业务代码，不代表取消工程验证，也不承诺所有未来需求都无需平台扩展。在声明式模型和能力包范围内可自由组合场景；新协议或特殊算法通过版本化扩展包增加。模拟器证明软件行为可重复，真机验收证明现场可用，两者不能互相替代。

最终交付的不是一组配置页面，而是可重复部署、可审计、可升级、可回退的项目包，以及由其生成的完整 EMS。平台价值以交付结果衡量：换厂商能否少改配置、异常能否直接定位、同事能否接手、升级能否保留现场定制、回退能否保留运行历史。

最终结果是一套以 IoT 无代码开发交付平台为底座、以 EMS 为行业应用的产品。它把设备接入、物模型、规则、画面、仿真、部署和升级统一成可复用能力。交付人员与终端客户使用不同工作台，但共享同一个项目包和运行数据。

交付人员将开发与实施合一，可以从已验收项目创建新站，只填写柜数、型号、地址和并网关系，由系统列出复用项、变化项与待确认项。换厂商时批量应用已验证 Profile，逻辑点自动关联，缺失回读等例外单独提示。常规策略只用模板，特殊要求才打开决策表或状态机。现场按“尚不能投运”清单逐项查看原始读数、映射和验证步骤并复验，旧站地址、凭据和控制授权不会自动带入，新设备默认待机，全程不碰代码。新厂商用声明式 Profile 接入，新协议或算法用版本化扩展包补充，不编写自由脚本。

项目包是唯一可版本化的工程交付资产，包含模型、适配器、规则、画面、仿真场景、部署参数、迁移与验收要求，全流程共用。发布只是项目包上的一个动作，自动完成预检、仿真、打包、迁移、部署和证据生成，不再单设交付中心。验收自动汇总通过项、遗留项以及仿真与真机证据，让同事从上次位置继续。升级按旧版基线、现场定制和新版模板对照，冲突由交付人员确认；需要时回退工程配置，保留新增报警、操作和审计，恢复控制前重新读取设备状态，不回放旧命令。

运行时形成“采集→物模型→规则策略→仲裁→命令回读→追溯”的链路。EMS 行业包提供储/光/充及可削减资源的能力、互锁、分配和联合调度。ResourceGroup 跨 Plant 不跨 Site，一个 EnergyUnit 仅属一个有功组，所有目标只有一个仲裁写口。每个 PCC 明确反馈电表和受影响资源，跨 Plant 后仍逐 PCC 验收，不能用全站净额掩盖局部反送。仲裁顺序为安全、防逆流、需量、集群或站级计划、电价，并依据 BMS、SOC、温度、在线状态及数据时效限制能力。平台支持 96 点计划与 15 分钟滑动需量：空缺时段不填零，窗口缺 bin 时不进行预测性削峰；验收项见 A08、A09。

新柜体默认待机，验证点位、方向、互锁和读写后才能启动。过期或坏值不授权控制。设定回读按设备编码和分辨率比较，且必须由提交后的新样本关联确认；实际功率另按容差和持续时间判断，因此“设定已确认”与“功率跟踪偏差”可以同时存在。故障动作按场景确定执行者、动作、反馈和恢复条件，不一律置零；失联时回退也可能无法送达，必须显示结果未知。恢复控制前重新读取设备状态并人工确认。

技术上保持一个 Go 业务服务和离线 Docker 交付。NATS/JetStream 负责配置与热状态，审计与命令日志当前为追加式 JSONL；PostgreSQL/TimescaleDB 与幂等 Outbox 属于目标架构，尚未实现，不得作为已交付能力对外声明。协议现状为 Modbus 闭环、OPC-UA 声明式接入、MQTT 仅上行遥测（下行命令与设备凭据/ACL 尚未实现）；CAN、HTTP-REST、OCPP 及外部 Broker 作为扩展。

终端客户拿到完整 EMS：可查看总览与 SCADA、处理报警、执行启停和人工功率控制、查询追溯、管理历史与权限，并完成备份恢复和版本升级，无需理解平台或代码。

验收看交付人员能否独立配出储能和光储充项目、适配多个厂商、验证故障断线、完成升级回滚并重复部署。模拟器只作为软件证据，M5 真机、多厂商互操作、性能及独立用户试用单独签收。最终目标是：项目能交付、运行能解释、异常能定位、版本能恢复。

逐项验收以 `docs/acceptance-map.html` 为准。A17（项目包导出导入）、A18（应用资产生成）、A19（包级一键发布）尚未实现，完成前只声称"EMS 无代码交付"，不声称"通用应用开发平台"。
