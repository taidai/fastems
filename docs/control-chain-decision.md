# EMSCore 控制链路 · 执行语义定案

日期：2026-11-08
状态：13 个决策经 grill 定案。其中 Q1、Q4、Q10 已被 2026-11-11 补充定案覆盖（见文末），实施与验收以补充定案为准；其余 10 条仍有效。

## 目标控制链

```
规则引擎（决策表）→ 功率请求
  → Site Scheduler（站级：跨站协调，硬优先级仲裁）
    → Plant Scheduler（电站：AllocateEnergy 能力分配）
      → Cabinet Controller（柜体：DispatchCabinet 拆解 + 安全门 + 互锁）
        → Command Engine（校验/安全/超时/回读确认/审计）
          → Device Adapter → Driver(Modbus) → 设备
  ← 遥测/状态/SOC 反馈（更新实时能力与可分配能力）
```

## 关键语义

- **动态能力**（Q6/Q7）：可分配功率 = min(额定, BMS 允许, SOC/温度约束)，充放分开，1s 刷新。
- **仲裁**（Q8）：安全约束永远赢，硬优先级可解释、可追溯。
- **安全兜底**（Q4/Q5/Q9/Q10）：人工优先、超时回退、安全互锁三道闸，保证"Controller 决定如何安全执行"。

## 2026-11-11 补充定案：PCC、命令确认、故障动作、需量与回滚

本节覆盖此前“故障一律置零”和“回滚即恢复数据库快照”的绝对化表述。以下口径作为后续实现与验收依据。

### 1. 资源组必须逐个并网点验收

- 每个 EnergyUnit 同一时刻只能属于一个有功分配组；每个受控目标只有一个最终写口。
- 每个 PCC 必须明确反馈电表、购售方向、数据时效、可选三相点位，以及能够影响该并网点的资源清单。调度与追溯必须能回答“这次动作影响哪个 PCC”。
- 跨 Plant 分组后仍逐 PCC 计算和验收，不能用全站净额掩盖局部反送。T19 的 A1 反送 30 kW、A2 购电 30 kW 时，全站合计为零，A1 仍必须判定越限并记录原因。

### 2. “设定已确认”与“功率跟踪偏差”是两种结果

- 设定回读按设备编码、数据类型和分辨率比较，禁止直接比较未归一化的浮点值。只有能够关联到本次命令、且采样时间晚于提交时间的设定回读，才能确认该命令。
- 与本次命令无法关联的同值样本，只能说明当前设定一致，不能补认历史命令成功。
- 实际功率使用设备/场景配置的容差和持续时间另行判断。下发 100 kW、设定回读 100 kW、实测持续 82 kW 时，界面同时显示“设定已确认”和“功率跟踪偏差”，不得合并成“执行成功”。
- 请求、分配、提交、设定回读和实测功率分别留痕，并记录命令关联 ID、采样时间与跟踪状态。

### 3. 故障动作按场景验证，不设全局置零

每个故障场景必须配置并验证：触发条件、执行者、动作、反馈、失联结果和恢复条件。

- 可选动作包括保持已确认安全值、限功率、停止充电、停止放电、停机或联动光伏；是否置零由设备及现场验证决定。储能吸收富余光伏时，充电置零可能加重反送，不能默认它一定更安全。
- 执行者可以是平台控制器、设备本地保护或经过验证的本地联动。通信失联时，回退命令可能无法送达，界面必须显示“结果未知”并报警，不能宣称已经安全停机。
- 本地设备的超时停机或光伏联动只有完成对应厂商和现场验证后才能启用。
- 恢复前重新读取设备状态、核对控制权，经人工确认后启动；不得因故障消失或版本回退自动恢复功率输出。

### 4. 96 点计划与 15 分钟滑动需量

- 96 点计划定义每个 15 分钟时段的目标、版本和生效范围；缺失时段表示无计划目标，不自动填零。
- 滑动需量窗口为 `(t-15min, t]`，滑动步长 1 分钟，划分为 15 个一分钟 bin。每个 bin 至少需要一个新鲜有效样本，先求 bin 内平均功率，再求 15 个 bin 的平均值。
- 缺失 bin 时滑动需量不可用，显示缺样区间，不进行预测性削峰；安全互锁和独立的瞬时 PCC 限值仍按各自规则执行。
- 验收必须包含跨窗口边界回放，用同一块表核对窗口起点、滑动步长和缺样处理，证明固定窗口结果没有被误当成滑动窗口结果。

### 5. 项目包回滚保留运行历史

- 项目包是唯一可版本化的工程交付资产。升级按“旧版基线、现场定制、新版模板”三方对照，冲突项由交付人员明确选择，不能静默覆盖。
- 版本回退只回退工程配置与相应迁移，不删除或回滚升级后新增的报警、操作、命令和审计历史；历史采用只增不删的追加语义。
- 恢复控制前必须重新读取设备状态、核对控制权和项目版本，不回放旧命令。回退后默认保持自动调度关闭，完成状态一致性检查并由授权人员确认后再启动。

### 6. 换品牌的点位差异与异构控制边界

- **点位变化**：新供应商的功率、SOC、状态、设定和回读点可以不同。Profile 必须把厂商点位映射到标准能力，标明必需、可选和可替代来源；缺失或不等价时明确降级或阻止相关控制，禁止用默认点位静默代替。逻辑能力引用保持稳定，但物理映射必须重新验收。
- **管理边界**：一簇一管理时，簇是独立 EnergyUnit；多簇一管理时，管理器是 EnergyUnit，内部簇只作为其组成设备，不得在 ResourceGroup 中重复参与分配。最小可独立受控能力单元才是调度对象，不能机械按柜或按厂商划分。
- **功率与能量**：瞬时功率分配依据 kW、实时可用能力和约束；能量计划依据 kWh、SOC 与时间窗。522 kWh 与 261 kWh 不应影响功率分配的口径，但会改变可持续充放能量和计划可行性，不能只按铭牌功率或容量比例一刀切。
- **STS 变体**：有无 STS 会改变并离网拓扑、状态机和互锁。Profile 必须声明 STS 是否存在、状态是否可读、命令是否可控；未接入状态时不生成虚假位置，只有状态可读时仅作互锁输入，具备控制与回读时才允许执行切换。
- **验收场景**：至少覆盖新供应商点位重映射、单簇/多簇管理边界、522/261 kWh 混合容量以及有/无 STS 的互锁与恢复，分别保留映射、分配、状态机和回读证据。
