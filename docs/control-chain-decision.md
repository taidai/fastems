# EMSCore 控制链路 · 执行语义定案

日期：2026-11-08
状态：13 个决策经 grill 定案，作为控制链路实施（在能力级调度地基之上）的共识基线。

## 目标控制链

```
规则引擎（决策表）→ 功率请求
  → Site Scheduler（站级：跨站协调，硬优先级仲裁）
    → Plant Scheduler（电站：AllocateEnergy 能力分配）
      → Cabinet Controller（柜体：DispatchCabinet 拆解 + 安全门 + 互锁）
        → Command Engine（校验/安全/超时/回读确认/审计）
          → Device Adapter → Driver(Modbus) → 设备
  ← 遥测/状态/SOC 反馈（更新实时能力与可分配能力）
```

## 13 个决策

| # | 决策 | 定案 |
|---|---|---|
| 1 | 范围 | A：单柜储能 + Modbus 闭环，光伏/充电/多协议留扩展 |
| 2 | 三权分工 | A：规则引擎定策略、Scheduler 定分配、Controller 定执行 |
| 3 | 重试 | A：不自动重试，超时报"结果未知"+告警 |
| 4 | 回读确认 | B：回读严格相等才确认；超时自动回退安全值 |
| 5 | 人工指令 | A：人工优先，接管后停止自动，显式恢复 |
| 6 | 动态能力 | A：读 BMS 允许充/放 + SOC/温度约束，min 合成，1s 刷新 |
| 7 | 能力方向/约束 | A：充放分开；SOC 越界剔除方向，温度越限降额、超限剔除 |
| 8 | 多目标仲裁 | A：硬优先级——安全 > 防逆流 > 需量 > 计划 > 电价 |
| 9 | 互锁 | A：安全互锁（故障/越限硬停机，人工确认解除） |
| 10 | 安全值 | A：回退到上一个已确认值，无确认值回 0 |
| 11 | 爬坡/死区 | A：爬坡默认 10 kW/s，死区 5 kW，均可配置 |
| 12 | 协调周期 | A：站→站→柜每 1 秒重算 |
| 13 | 向上反馈 | A：轮询（EnergyScheduler 每秒读能力/状态/告警） |

## 三个"用户反推荐"的决策（⚠️，确认是有意的）

1. **Q4=B 回读严格相等 + 超时回退安全值**：比"保持未知值"更保守——超时自动回退可能造成二次扰动，但 Q10 用"回退到上一个确认值"缓解了这一点。
2. **Q3=A 不重试**（用户接受我的推荐，但和图中 Command Engine 的「重试」字面不同）——这是有意的安全取舍。
3. 其余 11 题均按推荐。

## 关键语义

- **动态能力**（Q6/Q7）：可分配功率 = min(额定, BMS 允许, SOC/温度约束)，充放分开，1s 刷新。
- **仲裁**（Q8）：安全约束永远赢，硬优先级可解释、可追溯。
- **安全兜底**（Q4/Q5/Q9/Q10）：人工优先、超时回退、安全互锁三道闸，保证"Controller 决定如何安全执行"。
