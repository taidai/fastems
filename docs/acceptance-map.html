反复交付主链

人只做判断与例外处理，其余由系统自动完成并留证
① 从已验收项目创建人｜填柜数、型号、地址、PCC系统｜列出复用 / 变化 / 待确认项
→
② 批量换厂商人｜选 Profile，确认缺失项系统｜整批应用，逻辑点自动关联
→
③ 模板配策略人｜填计划、需量、适用 PCC系统｜同一输入试算，给出原因与缺口
→
④ 现场联调人｜按阻塞清单逐项复验系统｜显示原值、映射、时效与步骤
→
⑤ 校验发布与交接人｜确认冲突项、签字交接系统｜预检、仿真、证据汇总
→
⑥ 售后升级与回退人｜只确认新版与定制的冲突系统｜保留历史，不回放旧命令
约束：复用资产但不复制旧站地址、凭据与控制授权；新设备默认待机；仿真证据与真机证据分开；交接不靠口头描述。

PCC 是约束维度，ResourceGroup 是成员覆盖层，都不是调度层级
Site 场站｜总目标 · 总约束 · 0..n 个 PCC
↓　并网关系：PCC 属 Site，Plant 通过并网点引用 PCC

1 × 522 kWh200 kWSOC 60%
簇就是独立受控单元；kW 用于功率分配，kWh/SOC 用于能量计划
簇即受控边界簇内 BMS/PCS 只是组成设备，不再产生第二层调度对象
无二级管理器不重复计数，也不参与 ResourceGroup 分配

管理器是受控单元，内部簇不参与分配（内部簇模型尚未实现，见 A16）
簇 1 · 130.5 kWh内部设备：不是 EU、不入组、只上报
簇 2 · 130.5 kWh内部设备：不是 EU、不入组、只上报
监测电表（Device）挂在 PCC 上做反馈或分项计量；不属 EnergyUnit，不入组，不参与 kW 分配
STS 绑定（非 EnergyUnit）三态：不存在 / 状态可读 / 可控且有回读；可被多个 EU 共享；只按实际映射参与互锁。模型尚未实现，见 A23。
Device → Point　PCS / BMS / Meter / IO / Fire。每个逻辑点带角色：测量 / 设定 / 回读 / 状态 / 报警，并声明必需、可选或可替代；缺失角色按规则降级或阻断，不用默认点冒充。
调度对象是 EnergyUnit，不是柜、不是设备型号。一个可调 EU 属 0..1 个有功组；一个受控目标只有一个写口。
换品牌＝点位重映射，不换逻辑能力功率、SOC、状态、设定与回读点可以不同；按标准能力重映射，缺失或不等价项明确降级或阻断，禁止用默认点位静默代替。
异构＝控制边界 + 功率/能量分离一簇一管理以簇为 EU；多簇一管理以管理器为 EU，内部簇不重复分配。功率看 kW 与实时能力，能量计划看 kWh 与 SOC。522/261 kWh 只影响能量可行性，不影响功率分配口径。
STS 与簇管理方式正交STS 是拓扑开关，没有有功能力；可挂在 PCC 边界被多个 EU 共享。只读时不生成位置、只作互锁输入；可控时命令走命令引擎，不进入功率分配。
必须始终成立的不变量 PCC 是仲裁与约束维度，不拥有写口 一个可调 EnergyUnit 同时只属 0..1 个有功组 组上限是瞬时 kW（含方向与有效期），由 Site Scheduler 持有并分解 组是约束容器，不是第三个分配器 监测设备与内部簇不进入可调能力与分配 逐 PCC 限值优先于组共享上限

团队协作与变更纪律

谁负责什么、改动如何传染到验收
平台维护者负责：协议适配器、规则引擎内核、点类型、扩展包、内核版本。
不碰：客户项目内的点位与策略配置。
产出：内核版本 + 全量回归 + 变更说明
交付人员负责：建项目、换 Profile、配策略、现场联调、发布交接、升级回退。
不写：业务代码与自由脚本。
产出：项目包 + 逐项证据 + 遗留项
验收人负责：按 A01–A23 逐行签收、核对证据类型与数值、判定 S/I/H 是否混用。
不改：配置与阈值。
产出：签收记录 + 未通过项的阻塞说明
终端客户负责：监控、报警处理、启停与人工功率、追溯查询、备份与升级操作。
不碰：配置、发布与权限模型。
产出：使用反馈与故障现象描述
改内核或协议平台维护者执行：新扩展包 + 全量回归 + 平台版本号提升；不得直接改客户项目内的点表。
改点表或映射交付人员执行：A15 逐点复验 + 更新映射 CSV + 重新确认阻断项，旧证据作废。
改策略或阈值交付人员执行：A03 金标准表新增一行并冻结，重新试算；未更新金标准的改动不得发布。
