# EMS 团队反复交付工作流

目标：服务反复交付 EMS 项目的团队与终端客户。重复交付不是复制一个站点，而是复用已验收资产，只处理本次变化和例外。

| 环节 | 交付人员只做这些 | 平台必须自动完成 |
|---|---|---|
| 建项目 | 选择“从已验收项目创建”，填写柜数、型号、连接地址和并网关系 | 列出可复用项、变化项、待确认项；旧站地址、凭据和控制授权不得自动带入，新设备默认待机 |
| 换厂商 | 选择已验证 Profile，批量应用到本批柜体 | 按标准能力关联功率、SOC、状态等逻辑点到原画面和策略；缺少设定回读等例外单独列出受影响的控制和验收项 |
| 配策略 | 选择策略模板，填写计划、需量限值和适用 PCC；只有特殊要求才编辑决策表或状态机 | 使用同一组输入试算，展示每台柜是否动作、动作原因、胜出来源和缺口 |
| 现场联调 | 按“尚不能投运”清单逐项处理并就地复验 | 每项显示原始读数、映射结果、数据时效和验证步骤，例如“3 号柜方向待确认”“PCC-2 主表过期”；未解决前不得自动投运 |
| 验收交接 | 查看通过项和遗留项，把项目交给下一位同事 | 自动记录项目版本、输入、下发、回读、实测、操作者和时间，区分仿真与真机证据，支持从上次位置继续 |
| 售后升级 | 打开客户那次操作的追溯，确认新版与现场定制的冲突项 | 汇总版本影响，保留历史和定制；回退工程配置后重新读取设备状态，不回放旧命令 |

## 全局约束

1. **复用资产，不复制秘密**：站点地址、设备凭据和控制授权必须重新绑定、重新确认。
2. **默认不能投运**：只有全部阻塞项解除后才能启动自动调度；每个阻塞项都必须可定位、可复验。
3. **证据自然产生**：测试和控制自动形成时间线，不在验收前补写材料；仿真证据与真机证据分开。
4. **交接不靠口头描述**：项目包、现场定制、验收状态和操作追溯共同构成同事接手与售后诊断的上下文。
