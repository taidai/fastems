# M5 现场验收执行手册

版本：2026-11-05
适用：恩玖 PCS、ESBCM 储能 BMS、至少一台电表、华为光伏逆变器。
原则：**模拟器通过不替代真实链路；本手册的签字只在现场真实设备上完成。**

## 1. 现场前置条件

- 工控机与设备供电稳定；急停、消防、绝缘与接地按现场规程执行。
- RS485 接线完成，A/B 不反接，屏蔽与终端电阻按厂家要求；TCP 设备与工控机同网段。
- 已确认每个设备的协议、站号、波特率/端口、寄存器地址基准（0-based/1-based）和字序。
- 已由设备负责人书面确认允许写入哪些点；计量表默认全项禁写。
- 已停止其他主站，保证一条总线只有一个主站。
- 已完成完整数据目录离线备份；知道恢复步骤。

## 2. 设备与 Profile

| 设备 | Profile ID | 协议来源 | 现场还需确认 |
| --- | --- | --- | --- |
| 恩玖 PCS | `enjo-pcs` | PCS 通用协议 V1.20/V1.27 | 0x500E 与旧 0x0D57 功率设定地址、写授权、SN/版本 |
| 高特 ESBCM BMS | `esbcm-bms` | ESBCM V1.18 | 站号、LAN/RS485、协议版本 200/201、禁读区 |
| DTSD3366D 电表 | `dtsd3366d-meter` | DTSD3366D V1.03.2 | FC53 型号、CT 变比、正/反向语义 |
| 雅达 YD2037 电表 | `yd2037-meter` | YD2037Y-F V1.09 | 0xAB80 型号、字序、正/反向语义 |
| 华为逆变器 | `huawei-inverter` | Huawei Modbus V3.0 | 型号/额定功率、功率控制范围与极性 |
| 吉瓦时代 MPPT | `jiwa-mppt` | Jiwa V2.5 | 协议版本、站号、限功率写授权 |

所有 Profile 当前均为 **未现场验证**。在部署页选择 Profile 后：

1. 点“下载 Profile 点表”，得到 `名称,站号,地址,类型,数据格式,只读,缩放,偏移,单位` CSV；
2. 在“点表校验”中先 **预检**，确认地址、类型、缩放、只读标记；
3. 只用现场确认过的点做导入；不确定的写点保持只读或删除；
4. 首次接入先读 0x6000/0xAB80/协议版本等特征值，核对地址基准与字序。

Profile 只提供 EMS 需要的精简点位，不是厂商全量点表；单体电压/温度等数组未默认展开。

## 3. 自动执行检查（只读默认）

脚本：`frontend/m5-site-acceptance.mjs`

配置示例：

```json
{
  "site": "台山储能站",
  "devices": [
    {
      "name": "1 号 PCS",
      "channel_id": "<通道节点 ID>",
      "server_id": 1,
      "profile_id": "enjo-pcs",
      "required_points": ["交流输出总有功功率", "工作状态", "直流功率"],
      "control": {
        "target_node_id": "<有功功率设定节点 ID>",
        "value": 10,
        "expected": 10,
        "tolerance": 0.2,
        "readback_node_id": "<交流输出总有功功率节点 ID>",
        "restore": 0,
        "timeout_ms": 5000
      }
    }
  ]
}
```

只读运行：

```bash
FASTEMS_URL=http://127.0.0.1:8080 \
FASTEMS_ADMIN_PASSWORD='现场本机密码' \
M5_CONFIG=/path/to/site.json \
node frontend/m5-site-acceptance.mjs
```

允许控制/回读（仅在现场负责人书面授权后）：

```bash
M5_ALLOW_WRITE=1 ... node frontend/m5-site-acceptance.mjs
```

脚本检查：登录、最近验收报告、通道存在与健康、站号设备健康、Profile 是否存在/是否已验证、必读点位的值与新鲜度（默认 15 s）；写入模式还会写入目标、等待回读匹配并恢复。报告写到 `evidence/m5-site-*.json`。它**不**自动完成断线、恢复、过期阻断和重复提交的人工检查。

## 4. 必须由现场人员完成的检查

对每台设备逐项记录操作人、时间、对象和结果：

1. **采集**：断开再恢复通信，确认离线、恢复、质量与时间戳变化；过期值不触发新动作。
2. **控制**：在授权下写一个安全的小目标，确认设备动作、回读、超时“结果未知”路径。
3. **断线**：拔掉 RS485/TCP，确认通道离线、报警产生、自动动作被阻断；恢复后重新采集。
4. **重启**：重启工控机，确认通道、账号、画面、规则、历史和报警恢复；不重放已命中的规则。
5. **重复提交**：对同一目标重复下发，确认命令幂等或明确返回已有请求状态。
6. **越权**：用查看者账号尝试写点、改配置、发布规则，确认服务端拒绝。
7. **备份恢复**：停止应用，复制完整数据目录，在另一数据目录恢复并登录，确认节点/历史/规则/画面完整。
8. **PCS 分配**：4 台 PCS（至少 1 台离线、1 台限功率）执行 800 kW 请求，确认按能力分配、逐台回读、超时停止、重启不重放。

## 5. 通过标准

- 上述自动检查无 `failed`；Profile 的“未验证”在签收前必须改为现场验证。
- 8 项人工检查全部有证据：截图、报告 JSON、操作人、时间、设备序列号。
- 任何一项未完成，M5 不得签字；模拟器结果只能作为回归，不作为现场签收。
- 签字后更新 `GOAL.md` 的 M5 状态和 `evidence/final-acceptance.md`。
