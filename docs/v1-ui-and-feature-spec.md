# v1 界面逻辑与功能细化规格

日期：2026-11-06
范围：v1 软件侧，按“命名命令 → 审计 → 工具链 → 报文 → 通信质量/历史/分配器 → 报警维护/Profile 验证”的顺序落地。目标是功能一次设计清楚，避免后续反复改入口和状态模型。

## 1. 全局界面原则

1. **一个对象一个工作区**：同一对象只保留一个主入口。端口/单元归“通道”；设备命令归“通道 → 单元 → 设备模型”；报警记录归“报警与事件”；审计归“配置 → 审计”。
2. **状态先于操作**：每个可执行动作前显示对象状态（在线/离线、质量、是否验证、是否映射）。不可执行时按钮禁用并说明原因，不弹通用错误。
3. **渐进披露**：列表只显示决策需要的列；详情/配置在抽屉或页签中展开，不把所有字段堆在一屏。
4. **一次确认，结果可追踪**：控制写入必须确认；执行后显示“已接受 → 执行中 → 已回读/结果未知/失败”，并给出 request_id，方便审计与现场对时。
5. **空状态给下一步**：没有 Profile、没有映射、没有命令时，直接给“先做什么”，不显示空白表格。
6. **不制造数据**：缺失/过期显示“—”，质量用“正常/过期/无值/离线”，不使用猜测值。
7. **一屏不滚动**：页面级、舞台级、横向滚动为 0；长列表只在表格/抽屉内部滚动。
8. **可追溯**：配置保存、命令执行、报警确认、规则发布都进入审计；界面提供“查看审计”入口。
9. **键盘与触摸**：Esc 关闭弹窗；10.1 寸下按钮最小 44px；表格行可整行点击；确认按钮与取消按钮位置固定。
10. **文案说结果**：按钮写“保存设备模型”“执行命令”，反馈写“已保存”“已回读”，不用“提交/操作成功”这类模糊词。

## 2. 通道 / 设备模型 / 命令（已落地）

### 2.1 入口

- 页面：通道 → 端口配置 → 选中端口 → 单元列表。
- 每个单元行提供“设备模型”（管理员/实施）或“命令”（操作员/查看者只读）。
- 单元行不再单独放“查看点位”之外的第二套配置入口；点位仍由“点位表”统一管理。

### 2.2 设备模型页签

1. 选择 Profile 后，按变量名称自动匹配同站号点位；匹配数量立即显示。
2. 映射表列：Profile 变量、地址、单位、读写、映射点位、状态。
3. 状态只分三种：已映射、需映射（命令会写该点位）、可选（遥测等非命令点位）。
4. 保存前不强制所有遥测映射；命令需要的点位未映射时，保存成功但命令标记“不可用”，并给出原因。
5. 设备名称、业务节点、验证说明、完成现场验证勾选一起保存；Profile 未验证时保留“未验证”提示。
6. 保存后自动切到“命令执行”，避免用户再找入口。

### 2.3 命令执行页签

- 每个命令卡片显示：命令名、目标点位/写入值、执行按钮。
- 不可用命令显示原因：未映射点位、映射点位不存在、点位只读。
- 执行前确认框包含对象、目标、写入值和“会等待回读”。
- 结果状态：
  - 已接受：请求已进入队列；
  - 执行中：已下发，等待回读；
  - 已回读：读回值符合预期；
  - 结果未知：超时，设备可能已执行，禁止自动重试；
  - 失败：写入被拒绝或通道错误。
- 显示 request_id，便于审计与日志对齐。
- 设备离线/点位过期时禁用执行并说明原因。
- 重复点击使用同一 request_id 的幂等语义；界面不生成两次不同请求。

### 2.4 后端契约

- `GET/PUT /api/modbus/{channel}/units/{server}/model`
- `POST /api/modbus/{channel}/units/{server}/commands`
- `GET /api/modbus/{channel}/units/{server}/commands/{request_id}`
- 绑定保存在通道节点的 `easyemsUnitModel` 点（key=站号），重启恢复。
- 命名命令使用 `command.Manager` 的幂等、回读、超时/unknown 语义；不另写一套执行器。

## 3. 审计日志（下一步）

### 3.1 入口与布局

- 配置 → 审计日志（仅管理员）。
- 顶部筛选：操作人、动作、结果、时间范围；按钮“查询/重置/导出 CSV”。
- 表格列：时间、操作人、动作、对象、详情、结果、IP。
- 点击行打开详情抽屉，显示完整 detail 和 request_id/对象 ID；不显示密码、令牌或请求体。

### 3.2 记录范围

- 登录/退出；
- 通道/端口/点位新增、修改、删除、导入、停用/启用；
- 设备模型保存、命令执行与结果；
- 规则保存草稿、发布、启用/停用；
- 报警确认、关闭、维护；
- 用户/角色/权限变更；
- 设置变更（电价、显示、历史保留）。

### 3.3 记录规则

- 只记录操作者、动作、对象、结果、来源 IP、时间、可选 detail；绝不记录密码、令牌、完整请求体。
- 失败也要记录（越权、参数错误、设备离线、回读超时）。
- 保留上限可配置；默认按时间倒序查询最近 N 条。

## 4. 原始报文查看器

- 入口：通道 → 运行状态端口卡片或单元命令旁“报文”；不新开页面。
- 抽屉内容：时间、方向（收/发）、HEX、对端；全部/收/发过滤；暂停、清空、复制、重连。
- 运行时只保留有界环形缓存（例如每通道 500 帧），不持久化、不影响采集。
- 报文查看需要操作员及以上权限；不显示业务密钥。

## 5. 通信质量统计

- 通道运行状态增加：轮询成功率、平均/最大延迟、错误分类（超时/CRC/异常码/断线）。
- 单元列表增加每个站号的健康与最近成功轮询；点击进入点位/报文。
- 统计窗口：最近 5 分钟、1 小时；数据来自运行时内存，重启归零并明确标注。
- 与 V1-11 的“通信质量统计”对齐，不新增第二套采集。

## 6. 历史保留上限

- 配置 → 运行设置增加“历史保留条数”（站点级）；保存到根节点配置点。
- 应用后显示“重启生效”或运行时热更新；查询页显示当前上限。
- 超限时按时间淘汰最旧样本；CSV 导出保持当前筛选。

## 7. 分配器目标入规则编辑器

- 规则动作目标类型：点位 / 分配器。
- 选择分配器时，动作值作为总目标；`lastCheck` 显示分配明细（每台目标/实际/确认状态/原因）。
- 与现有输出所有权校验一致：同一分配器只能被一张已启用规则拥有。

## 8. 报警声音、维护与统计

- 显示设置：声音开关、音量、试听、静默时段；纯本地 Web Audio，不引入通知组。
- 报警页签：记录 / 类型 / 统计 / 维护。
- 维护：对某告警类型或点位设置“维护到某时间 + 原因”，期间不重复产生新告警；已有活动告警可确认/关闭。
- 统计：今日/昨日未处理/已处理、7/30 天趋势、设备排行。
- 所有维护操作进审计。

## 9. Profile 验证记录

- 设备模型保存 `verified`、验证人、日期、设备序列号、核对说明。
- 未验证 Profile 在部署页、设备模型和命令页持续显示“未验证”，不因保存而变成已验证。
- 提供导出验证记录（CSV/交付报告），作为 M5 现场证据。

## 10. 一步到位验收清单（每个功能都按此检查）

1. 数据模型：存在哪个节点/点，重启是否恢复。
2. 权限：管理员/实施/操作员/查看者分别能做什么，越权是否 403。
3. 正常路径：界面完成一次完整操作并回读。
4. 失败路径：离线、过期、未映射、只读、超时、重复提交、非法参数。
5. 可解释：界面显示原因和 request_id/对象 ID。
6. 审计：成功与失败都留痕，且无敏感信息。
7. 布局：1669/1600/1280/1366/1024 无页面/舞台/横向滚动。
8. 回归：`scripts/verify.sh` 通过；真实设备项单独标注未验证。
